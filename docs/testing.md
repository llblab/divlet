# Testing

Development runs source files, not `dist/`. Root `npm test`, start/demo and Pi/MCP test scripts use `scripts/source.mjs`, which propagates `--conditions=divlet-source` via `NODE_OPTIONS` to child processes. Focused checks use `node scripts/source.mjs --test …`; the same runner can launch a source browser script. Run from the checkout root. The workspace includes `.`, `web`, `cli`, `mcp`, `pi` and `plugins/*`; each adapter owns its tests in its top-level `<id>/tests/`.

| Check | Command | Covers |
| --- | --- | --- |
| Unit | `node scripts/source.mjs --test` | Model, project, codec, styles, runtime, server, launcher, import, history, safety, output ownership, static/site builds, the Pi adapter (`pi/tests`, with CLI/MCP tests in their own adapter packages), plugins (`plugins/*/tests`) and package contents. |
| Browser (all) | `npm run test:browser:all` | The 36 real Chromium suites in `web/tests/`: `validation`, `run`, `responsive`, `layout-wrap`, `site`, `fullscreen`, `settings`, `interact`, `selection-completion`, `size-editor`, `controls`, `history`, `features`, `agent-status`, `chat`, `spacing`, `toolbars`, `appearance`, `font-containers`, `reimport`, `chrome`, `fluid`, `snapshots`, `launcher`, `launcher-errors`, `native-collections`, `projects`, `security`, `static`, `native-default`, `landing`, `preview-links`, `text-edit-render`, `toast-priority`, `browser-mcp`, `pages`. Most have a `test:<name>` script (`test:spacing`, `test:chrome`, …); `appearance`, `reimport` and a few others run only through this command or through a combined script (`test:controls`, `test:launcher`, `test:source`). |
| History | `npm run test:history` | Core point/replay and board HTTP regressions, followed by the dedicated real Chromium whole-project acceptance suite (`history.mjs`); basic row/keyboard/phone/race checks also live in `controls.mjs`. |
| PEN fidelity | `npm run test:pen-fidelity -- /absolute/path/to/file.pen` | Renders every root frame of a caller-supplied `.pen` (no authored PEN example is bundled) from the native projection and from the converted Divlet frame in Chromium and requires identical pixels; a flat, single-colour screenshot counts as a failure too, because an identical blank canvas would prove nothing. `PI_DIVLET_FIDELITY_LIMIT=N` samples the first N frames. The 68-frame, 3 195-instance result quoted in the changelog came from a design that is not part of this repository and cannot be reproduced from it. |
| Release | `npm run test:release` | Packs five tarballs (`@divlet/web`, `@divlet/core`, `@divlet/cli`, `@divlet/mcp`, `@divlet/pi`) and installs them into an empty directory. Checks the public library, CLI, board/client/plugin serving and installed MCP initialization, tools and board opening **without Pi**, including the installed CLI/MCP font scenario in Chromium before adding Pi peers. Checks the Pi adapter package entry and manifest against the installed product; this is not a real Pi session. Core excludes adapter and web implementation trees; web owns its client/portable ports with no core dependency. Both exclude tests and caches. Exercises the installed opt-in versioned compiler. Needs Chromium and the npm registry (or its cache); publishes nothing. |
| Release + real Pi | `npm run test:release:pi` | Adds required real Pi RPC and installed-font Chromium acceptance to `test:release`, using compiled consumer exports and an isolated test profile/mock provider. A missing or broken `pi` CLI fails rather than skips. Requires Chromium and a working local Pi; validated with Pi 1.5.2 on Node 22.19. Installs no global extension and touches no active session or account. |
| MCP | `npm run test:mcp` | Spawns the MCP adapter source entry through the source-condition runner and speaks its stdio transport for real: `initialize`, `tools/list`, tool calls with a domain refusal, two clients sharing one board (attachment, not a second writer), concurrent writes refused by revision, shutdown on EOF and board de-registration. |
| Browser MCP | `npm run test:browser-mcp` | `@divlet/core/browser-mcp` against bundled static fixture pages under a repository prefix in real Chromium: connect by URL, discovery, calls observed in the page UI, the official SDK client over the browser transport, concurrent correlation, timeouts and cancellation reaching the page, reload invalidation and reconnect with IndexedDB persistence, page close, fast failure without a provider and waiting for an asynchronous one, cross-origin redirect/navigation refusal, a hostile page (no host bindings, oversized and mismatched replies, instruction-like descriptions kept as data) and WebMCP through a draft-shaped stand-in. Chromium ships no native WebMCP, so real browser-agent interoperability is not proven. |
| Pages | `npm run test:pages` | The `scripts/pages-build.mjs` set served by a file-only server under `/divlet/`: the real board opens the landing with only static GETs and no errors, native-only affordances are absent, export runs in the page, an agent connects by URL, edits what the visitor sees, refusals stay tool errors, visitor and agent edits share one writer and History, and the browser copy survives a reload; canonical and explicitly listed legacy tool names share the browser writer. |
| Connect | `npm run test:connect` | `divlet-mcp --connect` started by the official SDK stdio client against the built Pages set, in both protocol eras. `mcp/tests/connect.test.js` (in `test:mcp`) covers the stdio side without a browser. |
| Contract | `npm run test:contract` | One canonical tool list and legacy alias identity; attachment to an older board using its original wire names; the JSON Schema and TypeBox renderings agreeing on required parameters; the agent vocabulary; a board running only the tools it publishes; the board registry (one live owner, stale entries removed). |
| Pi RPC | `npm run test:pi` | A real Pi in RPC mode with a scripted model: a board request reaches a divlet tool, changes the project and returns as a reply. Skipped when the `pi` CLI is absent. |

Frontend unit suites (`icons.test.js`, `modules.test.js`, `http-session.test.js`, `board-session.test.js`, plus the board-session type fixture) and the Chromium entry scripts belong to `web/tests/`. Server/model unit suites and shared core fixture builders remain in `core/tests/`. `npm test` discovers both domains' unit suites; `test:browser:all` runs the root source Chromium entries. The installed-only `web/tests/release/fonts.mjs` and `pi-fonts.mjs` instead run through isolated-consumer release checks (the latter only in required Pi mode); they are not additional source-browser battery entries. Frontend tests are excluded from served modules and published build assets.

`npm test` starts with `npm run typecheck`: the Node/core profile remains strict, with `checkJs: false` and most browser code excluded. A separate `tsconfig.web.json` uses DOM libraries, no Node ambient types and `checkJs: true` for `http.js`, `http-session.js`, `http-services.js` and `host.js`, plus the public web asset locator, portable ports and read-session type fixture. This is not full-client JavaScript checking.

The installed font scenario resolves only compiled `@divlet/core` public exports and installed CLI/MCP bins, asserts that checkout product sources/Pi peers are absent, then drives real device uploads through that CLI owner. A separately installed MCP peer attaches to the same URL and shares native patch/Undo/Redo history. Actual TTF/CFF WOFF2 advances, exact bytes/MIME, payload-free project/frame reads, overlap refusal, snapshot pixels, iframe lifetime and public-sidecar refusal are checked. An independently identified copy is edited without changing the original, then rebuilt after original/cache deletion. Explicitly curated fixture HTML/fonts and clean export render under a controlled static prefix after the boards stop; editor sidecars are not published. This is one conventional-name/font/Chromium scenario, not arbitrary static-host MIME compatibility, general private-content scanning, a real Pi session, registry installation or full asset acceptance. All local test-owned boards are closed; no existing board is restarted. A separate SIGTERM fault case starts the test-owned CLI/MCP and Chromium, then proves child exit and workspace removal through the same idempotent cleanup path. A 75-second internal deadline and bounded escalation precede the release runner’s 90-second timeout; this is not a hard real-time or arbitrary OS-failure guarantee.

`test:release:pi` additionally runs the Pi adapter’s existing RPC scenarios against the compiled installed entry, with compiled public model/project exports supplying its fixture and no installed `core/` source tree. Checkout code supplies only the test driver, local mock provider, font fixtures and Playwright. Its font case uses validated user routes for a blank frame, the actual device chooser for separate TTF/CFF WOFF2 registration and explicit family selection, then real model-directed Pi tools for weight patching, payload-free project/frame reads and shared Undo/Redo. Measured advances of 120/180px, exact bytes/MIME, the same iframe and 150px captured ink distinguish real matching from fallback. Model tool context is also checked for font payloads. All boards belong to one test-owned Pi process under a fresh `PI_CODING_AGENT_DIR`; ordinary stdin EOF must exit 0 before fixture removal. An internal 90-second deadline and owned-process escalation precede the release runner’s 120-second timeout. This is not arbitrary provider/format compatibility, Pi-specific independent-copy acceptance, credential/account testing or a hard real-time/OS-failure cleanup guarantee; SIGINT and forced escalation are not fault-tested by this case.

`npm run test:toast-priority` uses the browser clock with a connected but idle test host: the delayed agent-start warning must not replace a currently actionable Undo toast, and appears after that toast expires. This regression is included in the full source browser battery.

## Browser writer parity

`node scripts/source.mjs --test core/tests/browser-runtime.test.js` opens the landing in the Node runtime and in `BrowserRuntime` (with the same style compiler) and drives the same contract tool calls through both: patches, a no-op, stale refusals, inserts including sanitized HTML, move/wrap, invalid operations, components and dependent re-renders, frame create/duplicate/delete refusal, project tokens/CSS, Undo/Redo (global and frame-scoped), marks and reads. Models, rendered pages, component uses, results, refusal codes, history summaries (except the Node-only trash note) and the serialized project must be identical. It also checks what the browser writer refuses (assets, sites, `divlet_open`) and that a failing store keeps the accepted change with a diagnostic. It does not prove asset, font or site parity, which the browser writer does not implement.

## Portable kernel slice

`node scripts/source.mjs --test core/tests/validation.test.js core/tests/model-browser.test.js` checks shared admission/error identity, UTF-16/UTF-8 budgets (with an independent Node `Buffer.byteLength` oracle), full standalone-frame candidate/inspection witnesses, strict HTML round trips and cold default-provider behavior. `npm run test:browser:kernel` runs 38 primitive, 48 UTF-8, 53 frame, 111 declared-asset-reference and 3 immutable snapshot-session witnesses plus 12 actual-store local/shared-selection and 12 optional-service consumer checks as native browser ESM under a repository prefix. Primitive source is type-erased only; the model uses the shared esbuild profile in `scripts/browser-model.mjs` with the package's explicit browser style-port mapping and PostCSS's own optional-feature browser mappings. The actual browser has no Node globals/polyfills, model backend API, SSE route or dependency rescue. It verifies both the shared successful/refused operations and explicit absent declarative lowering. The browser entry is included once in the full battery. The release smoke separately bundles the installed compiled package and evaluates its frame/lowering behavior in Node; that is not installed-bundle browser execution. These checks do not establish full-project/component expansion, shipped native-browser SDK delivery or an offline editor.

Package regressions additionally enforce adapters → core → web, no web runtime or JSDoc/type back-edge into core/Node, sole client ownership, exact release pins and repeat-build equality. Installed checks compile public web/core contracts without Node ambient types and serve the actual client from the separately installed web package; they are local tarball checks, not registry publication.

The read-session gate is `node scripts/source.mjs --test web/tests/board-session.test.js web/tests/board-session-types.test.ts web/tests/http-session.test.js web/tests/modules.test.js`. It checks detached snapshot data, read-only capabilities, independent/reentrant unsubscribe, opaque payload and optional view-publication types, native selection/observation payload/reply/refusal, URL/header/error projection, dynamic fetch instrumentation, SSE decode/refusal/cleanup and real runtime-import discovery without JSDoc false positives. The kernel suite serves the actual store/util modules under fixed test host compositions: publisher absence has no HTTP/pending/toast and preserves local selection across host echoes/clear/model/frame pruning; held shared replies exercise mismatched/matching state echoes, stale successes/refusals, completion and failure feedback without granting an obsolete request pending authority. `selection-completion.mjs` proves the native focused duplicate/Delete selection-completion boundary. `run.mjs`, `history.mjs` and `security.mjs` exercise the integrated native board, held-request History authority and authenticated preview boundary. `run.mjs` additionally loads a fresh fixed host composition with only observation publication absent: real iframe measurements update locally after a DOM resize, with no publication timer/queued report, observations POST or server observation. Its earlier native measurement check is the positive control. The other Node services remain real in that case, so it is not static/offline board proof. The optional-service consumer checks use actual activity/project/store modules with inert canvas/sidebar/chat collaborators, not the whole UI: absent History/import services issue no startup/sidebar requests or import prompts; audit-only History cannot restore even when state claims navigation; native services retain captured restore targets and scan failure/dedup/import-action and captured-copy Open/refusal behavior. `node scripts/source.mjs --test core/tests/public-snapshot.test.js core/tests/landing.test.js` checks the build-side public-page projection: allowlisted state/descriptor fields, omitted editor/runtime metadata, script refusal, explicit presentation geometry/identity, safe sibling browsing references, and reuse of the verified landing public set without changing its bytes. The kernel browser suite also loads that projection as static JSON, validates its frame with the same browser model and reads it through the snapshot session. This is public inspection-data proof, not secret scanning, resource-graph certification, an offline board or deployment.

`node scripts/source.mjs web/tests/projects.mjs` also exercises the shared filesystem picker in a real browser with a controlled read-only listing port: late success/refusal suppression, immediate typing invalidation, disposal, stable file rows/double-click and folder-only filtering. Its native Open/Create/Save-copy cases retain backend refusal and source checks. `web/tests/settings.mjs` composes the same control for folder navigation/keyboard selection, verifies that picking only changes the draft, and retains explicit Apply, stale-version and output-collision checks. These are native-host filesystem UI checks, not browser/offline filesystem access.

## Format candidate

Run these from a source checkout:

- `npm run test:format`: Baseline for portable accepted/rejected JSON examples, normalization, project read/write stability, component addresses, plain CSS with no engine, the specification's example/tag lists and nullable override types. It also runs the reader audit as a regression gate. Type assertions are checked by `npm run typecheck`/`npm test`; Node's TypeScript stripping alone does not type-check them. This is not full standard conformance or a managed-HTML reverse-editing test.
- `npm run test:format:audit`: Standalone reader-boundary report. Its JSON identifies each input, the two readers' admission outcomes, project read/write stability and an unblocker when a retained invariant fails. It exits 0 on success or 1 on regression; runtime/I/O errors still fail rather than appearing as policy findings.

Fixtures live in `core/tests/fixtures/format/`, including a valid table and rejected context/paragraph/foster-parenting witnesses; every accepted frame's expanded static projection is checked. The baseline also checks exact override-metadata budget boundaries and preserved null-deletion/application-data semantics. `node scripts/source.mjs --test core/tests/model.test.js core/tests/codec.test.js core/tests/components.test.js` adds root/parent context and expanded-instance checks plus admitted simple-tree projection checks across all supported HTML tags. These bounded checks do not establish conformance for every possible tree or text value. The audit uses raw JSON value strings so numeric overflow is not erased by fixture serialization. These source-checkout tests are not installed package APIs. See [the candidate's evidence boundary](format.md#evidence-and-freeze-boundary).

The ordered CSS transition has a focused foundation gate: `node scripts/source.mjs --test core/tests/declarations.test.js core/tests/codec.test.js core/tests/format-types.test.ts core/tests/model-browser.test.js`. It covers declaration order/fallbacks, first-position set/remove operations, property case, input isolation, legacy-map equivalence and shared serialization in the current codec. Opt-in `validDeclarations` adds strict pair shapes, literal-versus-nullable-operation typing, shared CSS safety/value bounds and a retained reader refusal for list-shaped stored styles. `npm run test:browser:kernel` executes the same admission/refusal witnesses through real browser ESM without Node globals. These do not establish the complete unfrozen schema-1 target profile, list-shaped native wire fields or native cascade emission; those remain transition work.

Structural dependency admission has its own gate: `node scripts/source.mjs --test core/tests/requirements.test.js core/tests/format-types.test.ts`. It covers explicit native `{}`, unknown/exact renderer identity, closed JSON-data records, full-token IDs, opaque ASCII version bounds, input isolation and continued refusal of the not-yet-activated project field. A cold temporary copy with only `requirements.ts`/`validation.ts` proves there is no model/provider bootstrap dependency; `npm run test:browser:kernel` runs the same acceptance/refusal vectors by direct native browser imports with no Node globals or backend.

Native JSON text admission is tested with `node scripts/source.mjs --test core/tests/native-json.test.js core/tests/format-types.test.ts core/tests/browser-runtime.test.js`. Shared Node/Chromium vectors cover escape-equivalent duplicate names, independent scopes, string escaping/UTF-16 preservation, ordered arrays, finite binary64/positive zero and caller-owned UTF-8/nesting budgets. The Node gate additionally traverses 10,000 containers without a recursive reviver, checks private-source diagnostic redaction and verifies that opt-in refusal does not mutate already opened draft writers. This does not activate strict text decoding in draft readers; remaining integration is FORMAT-VALUES. `npm run test:browser:kernel` executes the same text decoder directly without Node globals or a backend.

The existing-source/cache boundary has a focused runtime gate: `node scripts/source.mjs --test core/tests/source-preservation.test.js core/tests/browser-runtime.test.js core/tests/runtime.test.js core/tests/output.test.js core/tests/resource-access.test.js`. It proves exact authored bytes/inode/mtime on open with default/custom output, empty/nonempty frames, missing-cache reconstruction, retained raw-source hashes without echo revisions, and ordinary edit/Undo/Redo persistence. Source replacement at both persistence reads refuses the stale candidate and retains the newer authored file; bounded reads, output ownership and no-link refusals stay covered by the surrounding runtime suites.

The renderer requirement seam has a separate focused gate: `node scripts/source.mjs --test core/tests/engine.test.js core/tests/no-engine.test.js core/tests/format-types.test.ts`. It covers explicit native CSS with installed/absent providers, exact and order-independent selection, receiver/input preservation, missing/version/ambiguity/capability refusals, compiler-error propagation and unchanged omitted-requirement draft behavior. `node scripts/source.mjs --test plugins/tailwind/tests/renderer.test.js plugins/tailwind/tests/renderer-types.test.ts` adds portable installed dependency/stylesheet identity, nested-resolution and missing-installation refusals, exact descriptor typing and a hostile project-local stylesheet witness. The witness proves both pinned required compilation and retained ambient draft behavior. These do not prove project `requires` admission, matched resource/inspector capabilities, cache-independent required project rebuilds or engine-disable conversion; those remain integration work.

## Native HTML stabilization

`node scripts/source.mjs --test core/tests/html-import.test.js core/tests/import.test.js` checks core-owned HTML admission without an HTML plugin registration, with no style engine, and through explicit `.html`/`.htm` opening, folder-page ingestion and re-import. It covers reported sanitization losses, preserved sources, existing destinations, listing policy, link refusal and unsupported input. ## CI release checks

`node scripts/source.mjs --test core/tests/npm-release.test.js` tests the Release workflow's OIDC/ref boundary, aligned manifests/lock pins, immutable archive identities, prior-attempt guard and serial publication checkpoints with injected effects. Its fixture packs real local archives without running lifecycle hooks; it never publishes or changes credentials. The mocked accepted-upload/404, mismatched-byte and command/read-failure cases prove refusal behavior, not live npm authorization. A loopback-only mock registry also drives the real npm CLI with the publisher's retry flags: an HTTP 502 must produce exactly one package PUT. The fixture uses an owned dummy token and disables provenance only for that local transport test; no public registry publication occurs.

The existing `core/tests/release/install-smoke.mjs` also accepts `DIVLET_RELEASE_MANIFEST=/absolute/path/manifest.json` to consume and check exact frozen archives instead of rebuilding them. Add `--registry --pi` to fetch packs and install by published names while comparing both pack and installed-lock integrity to that manifest. Without these options the ordinary local-tarball checks remain unchanged. Registry mode requires a manifest and an available real Pi CLI when `--pi` is requested. See [publication](publishing.md#github-actions-publishing) for the three CI jobs and activation gates.

## Conventions

- Assert actual state (project file, model, accepted version), not only that a request returned.
- Client module boundary: `node scripts/source.mjs --test web/tests/modules.test.js` resolves literal static/lazy/re-export dependencies across the board and plugin client roots, refuses missing/TypeScript targets and checks their local graph for cycles. Runtime-computed specifiers are not parsed; plugin roots are enumerated separately. `features.mjs` also exercises two-artboard clipboard paste and one-step Undo, checking that facade lifecycle exports retain function identity; `controls.mjs` covers creation/reveal, duplicate, delete and toast Undo. `features.mjs` also checks a refused component library followed by an accepted unrelated deletion (correct success name, captured versions, visibility and one toast Undo), a held deletion racing a real peer edit (refusal preserves the peer frame/revision/undo depth), consumer-before-library multi-delete with one grouped restoration; and overlapping hidden/missing targets sending no additional request, preserving the first command's visibility reservation and peer edit. Toast Undo coverage is immediate/non-interleaved, not a command-specific inverse under arbitrary concurrent history.
- History traversal: `node scripts/source.mjs --test core/tests/history.test.js` covers ordered atomic multi-step Undo/Redo, grouped multi-frame movement, settings/content and frame lifecycle (including exact source/model frame order), external reorder-only and mixed membership/reorder transactions, retained frame-scoped selectivity, bounded counts and unchanged state/source/output/stacks on later conflicts, injected pre-publication refusal or real output preflight rejection. It does not simulate every filesystem fault or redefine post-source generated-cache recovery. The multi-step success witness counts one persistence call and one accepted revision per traversal; this core-only suite does not establish browser behavior.
- History points: `node scripts/source.mjs --test core/tests/history-line.test.js core/tests/history.test.js core/tests/safety.test.js` adds grouped-frontier invalidation, stable return IDs, one-write point jumps, no-op navigation, stale/queued requests, branching, selective/untracked boundaries with legacy Undo/Redo preserved, mixed lifecycle/order, refusal authority, the real 200-group window, HTTP reads, restart isolation and no source serialization. Audit-only events do not move the cursor; net-equal group replay can move it without advancing the audit sequence. These are core addressing checks, not evidence of clickable browser state rows or persistent history.
- History HTTP: `node scripts/source.mjs --test core/tests/server.test.js` checks owner-advertised `history.navigation`, whole-project timeline reads despite audit filtering, grouped movement/settings/lifecycle traversal with one persist and forward return, current-point no-op, actor projection, stale/unavailable/malformed refusals, Origin/token-prefix boundaries and real symlink preflight refusal preserving state/source/stacks. Two held HTTP requests prove expected-point rechecking inside the writer queue. SSE coverage observes a point-only move without an audit sequence change; monotonic runtime revisions are not historical state addresses. Browser row evidence is scoped separately below.
- History UI: the History block in `node web/tests/controls.mjs` exercises point rows, forward return, branch/future removal, point-only refresh with unchanged audit seq, Enter/Space, focus retention, Home/End, phone/200% text containment, read-only audit and owner-capability absence/return without navigation dispatch. Deterministically held GETs test both stale B and stale A-future snapshots arriving after A → B → A; matching current IDs cannot retain a discarded future. Hidden History must not fetch a complete timeline on every edit. Held HTTP-400 and missing-timeline responses after an owner change must expose no old addresses, make no automatic retry during a bounded 400 ms observation and recover with one read on reopen; these are preservation checks, not a long-duration outage/reconnect soak. `node web/tests/history.mjs` adds a real live pointer drag whose partial frontier disappears and whose single state restores source/model and actual camera-projected canvas wrapper positions/dimensions. It restores grouped multi-frame content/settings/tokens/CSS/create/delete/order as one persistence/revision; checks edited text in two surviving iframes and restoration of a non-tail deleted frame (explicit survivor reordering is covered by the core suite); refuses real output symlinks and held stale UI requests without an accepted prefix; recovers after safety repair; reconciles selective/untracked boundaries; retains IDs on browser reload but not owner restart; and renders the real 200-group window independently of the smaller audit window, traversing its earliest/latest endpoints in one persist each. `npm run test:history` runs its core/HTTP prerequisites and this acceptance suite. These bounded scenarios do not simulate every filesystem fault, an unbounded retry soak or referenced-resource byte restoration.
- Expanded viewing: `node web/tests/fullscreen.mjs` checks immediate site content without a second control, ordinary frames kept distinct from the site's template, native fragments/keyboard cross-frame links/linked HTML with external local CSS and images, the same iframe, desktop/phone viewports, opaque site live updates and fresh editor return. `node web/tests/security.mjs` also replays the pre-view capability from a navigated document and rejects it, retaining no-referrer/no-model-leak and trusted post-reset editing. `core/tests/server.test.js` checks the accepted-map public route, read-only nonce/CSP boundary and private/missing file refusal using real manifest-derived metadata names, while retaining sidecar repair. This does not certify the separate scaled-canvas Play navigation path.
- Preview links: `node web/tests/preview-links.mjs` checks that in Play a same-page `#fragment` or bare `#` link scrolls the preview without a navigation or a request for a missing `files/` path, an unknown fragment stays put and the authored `href` is unchanged. A `page.html#fragment` or `./page.html` link to another artboard reveals and selects it and scrolls its page (a plain page link lands at the top), a link to an unknown page is named in a toast, and no iframe navigates.

# Testing

Development runs source files, not `dist/`. Root `npm test`, start/demo and Pi/MCP test scripts use `scripts/source.mjs`, which propagates `--conditions=divlet-source` via `NODE_OPTIONS` to child processes. Focused checks use `node scripts/source.mjs --test …`; the same runner can launch a source browser script. Run from the checkout root. The workspace includes `.`, `packages/*` and `plugins/*`; each adapter owns its tests in `packages/<id>/tests/`.

| Check | Command | Covers |
| --- | --- | --- |
| Unit | `node scripts/source.mjs --test` | Model, project, codec, styles, runtime, server, launcher, import, history, safety, output ownership, static/site builds, the Pi adapter (`packages/pi/tests`, with CLI/MCP tests in their own adapter packages), plugins (`plugins/*/tests`) and package contents. |
| Browser (all) | `npm run test:browser:all` | The 32 real Chromium suites in `web/tests/`: `validation`, `run`, `responsive`, `layout-wrap`, `site`, `fullscreen`, `settings`, `interact`, `selection-completion`, `size-editor`, `controls`, `history`, `features`, `agent-status`, `chat`, `spacing`, `toolbars`, `appearance`, `reimport`, `chrome`, `fluid`, `snapshots`, `launcher`, `launcher-errors`, `native-collections`, `projects`, `security`, `static`, `native-default`, `landing`, `preview-links`, `text-edit-render`. Most have a `test:<name>` script (`test:spacing`, `test:chrome`, …); `appearance`, `reimport` and a few others run only through this command or through a combined script (`test:controls`, `test:launcher`, `test:source`). |
| History | `npm run test:history` | Core point/replay and board HTTP regressions, followed by the dedicated real Chromium whole-project acceptance suite (`history.mjs`); basic row/keyboard/phone/race checks also live in `controls.mjs`. |
| PEN fidelity | `npm run test:pen-fidelity -- /absolute/path/to/file.pen` | Renders every root frame of a caller-supplied `.pen` (no authored PEN example is bundled) from the native projection and from the converted Divlet frame in Chromium and requires identical pixels; a flat, single-colour screenshot counts as a failure too, because an identical blank canvas would prove nothing. `PI_DIVLET_FIDELITY_LIMIT=N` samples the first N frames. The 68-frame, 3 195-instance result quoted in the changelog came from a design that is not part of this repository and cannot be reproduced from it. |
| Release | `npm run test:release` | Packs four tarballs (`divlet`, `@divlet/cli`, `@divlet/mcp`, `@divlet/pi`) and installs them into an empty directory. Checks the public library, CLI, board/client/plugin serving and installed MCP initialization, tools and board opening **without Pi**. Checks the Pi adapter package entry and manifest against the installed product; this is not a real Pi session. The product excludes adapter source trees, tests and caches. Exercises the installed opt-in versioned compiler. Needs the npm registry (or its cache); publishes nothing. |
| MCP | `npm run test:mcp` | Spawns the MCP adapter source entry through the source-condition runner and speaks its stdio transport for real: `initialize`, `tools/list`, tool calls with a domain refusal, two clients sharing one board (attachment, not a second writer), concurrent writes refused by revision, shutdown on EOF and board de-registration. |
| Contract | `npm run test:contract` | One tool list; the JSON Schema and TypeBox renderings agreeing on required parameters; the agent vocabulary; a board running only the tools it publishes; the board registry (one live owner, stale entries removed). |
| Pi RPC | `npm run test:pi` | A real Pi in RPC mode with a scripted model: a board request reaches a divlet tool, changes the project and returns as a reply. Skipped when the `pi` CLI is absent. |

Frontend unit suites (`icons.test.js`, `modules.test.js`, `http-session.test.js`) and the Chromium entry scripts belong to `web/tests/`. Server/model unit suites and shared core fixture builders remain in `core/tests/`. `npm test` discovers both domains' unit suites; `test:browser:all` runs each Chromium entry. Frontend tests are excluded from served modules and published build assets.

`npm test` starts with `npm run typecheck`: the Node/core profile remains strict, with `checkJs: false` and most browser code excluded. A separate `tsconfig.web.json` uses DOM libraries, no Node ambient types and `checkJs: true` for `http.js`, `http-session.js`, `http-services.js` and `host.js` only. The read-session type fixture also checks imported adapter types under the Node profile. This is not full-client JavaScript checking.

## Portable kernel slice

`node scripts/source.mjs --test core/tests/validation.test.js core/tests/model-browser.test.js` checks shared admission/error identity, UTF-16/UTF-8 budgets (with an independent Node `Buffer.byteLength` oracle), full standalone-frame candidate/inspection witnesses, strict HTML round trips and cold default-provider behavior. `npm run test:browser:kernel` runs 38 primitive, 48 UTF-8, 53 frame, 111 declared-asset-reference and 3 immutable snapshot-session witnesses plus 12 actual-store local/shared-selection and 12 optional-service consumer checks as native browser ESM under a repository prefix. Primitive source is type-erased only; the model uses the shared esbuild profile in `scripts/browser-model.mjs` with the package's explicit browser style-port mapping and PostCSS's own optional-feature browser mappings. The actual browser has no Node globals/polyfills, model backend API, SSE route or dependency rescue. It verifies both the shared successful/refused operations and explicit absent declarative lowering. The browser entry is included once in the full battery. The release smoke separately bundles the installed compiled package and evaluates its frame/lowering behavior in Node; that is not installed-bundle browser execution. These checks do not establish full-project/component expansion, shipped native-browser SDK delivery or an offline editor.

The read-session gate is `node scripts/source.mjs --test core/tests/board-session.test.js core/tests/board-session-types.test.ts web/tests/http-session.test.js web/tests/modules.test.js`. It checks detached snapshot data, read-only capabilities, independent/reentrant unsubscribe, opaque payload and optional view-publication types, native selection/observation payload/reply/refusal, URL/header/error projection, dynamic fetch instrumentation, SSE decode/refusal/cleanup and real runtime-import discovery without JSDoc false positives. The kernel suite serves the actual store/util modules under fixed test host compositions: publisher absence has no HTTP/pending/toast and preserves local selection across host echoes/clear/model/frame pruning; held shared replies exercise mismatched/matching state echoes, stale successes/refusals, completion and failure feedback without granting an obsolete request pending authority. `selection-completion.mjs` proves the native focused duplicate/Delete selection-completion boundary. `run.mjs`, `history.mjs` and `security.mjs` exercise the integrated native board, held-request History authority and authenticated preview boundary. `run.mjs` additionally loads a fresh fixed host composition with only observation publication absent: real iframe measurements update locally after a DOM resize, with no publication timer/queued report, observations POST or server observation. Its earlier native measurement check is the positive control. The other Node services remain real in that case, so it is not static/offline board proof. The optional-service consumer checks use actual activity/project/store modules with inert canvas/sidebar/chat collaborators, not the whole UI: absent History/import services issue no startup/sidebar requests or import prompts; audit-only History cannot restore even when state claims navigation; native services retain captured restore targets and scan failure/dedup/import-action and captured-copy Open/refusal behavior. Factory/type tests cover exact native routes/replies/refusals, read-only audit authority and a complete source-notification workflow. `reimport.mjs` checks the actual native source-change/copy/open path. The snapshot witnesses also run through the native-browser kernel suite; that does not establish an offline board or public-safe snapshot publication.

`node scripts/source.mjs --test core/tests/public-snapshot.test.js core/tests/landing.test.js` checks the build-side public-page projection: allowlisted state/descriptor fields, omitted editor/runtime metadata, script refusal, explicit presentation geometry/identity, safe sibling browsing references, and reuse of the verified landing public set without changing its bytes. The kernel browser suite also loads that projection as static JSON, validates its frame with the same browser model and reads it through the snapshot session. This is public inspection-data proof, not secret scanning, resource-graph certification, an offline board or deployment.

`node scripts/source.mjs web/tests/projects.mjs` also exercises the shared filesystem picker in a real browser with a controlled read-only listing port: late success/refusal suppression, immediate typing invalidation, disposal, stable file rows/double-click and folder-only filtering. Its native Open/Create/Save-copy cases retain backend refusal and source checks. `web/tests/settings.mjs` composes the same control for folder navigation/keyboard selection, verifies that picking only changes the draft, and retains explicit Apply, stale-version and output-collision checks. These are native-host filesystem UI checks, not browser/offline filesystem access.

`node scripts/source.mjs --test core/tests/asset-context.test.js core/tests/model-browser.test.js core/tests/data-urls.test.js core/tests/html-import.test.js` checks native resource URL contexts, canonical identity, strict HTML carriers, expanded component/tag override refusal, foreign direct-URL namespace isolation and accepted-writer refusal without source/history changes. `node scripts/source.mjs --test core/tests/source-assets.test.js core/tests/asset-upload.test.js` checks schema-1 source/patches, aliases and literals, MIME-before-extension delivery, render invalidation, guarded Undo/Redo, foreign CSS/srcset/compiler/fragment namespace closure, literal clipboard retention, missing/unsafe-reference and collision refusal, unused-byte copy isolation, source-envelope bounds and cache deletion/rebuild. Font family/upload controls and far-zoom capture remain separate acceptance work.

`web/tests/appearance.mjs` additionally exercises the native family selector: Default/generics, declared stored faces and real loading, literal comma/parenthesis names, fallback/priority preservation, multi-selection Undo and whole-selection font/all shorthand refusal (including important resets), plus effective computed-family checks under an important stylesheet without silent priority escalation and keyboard menu/focus recovery. It opens a separately owned project with no style engine and proves actual font rendering, plus phone/200% exact-value keyboard panning. This is not device-upload or far-zoom-font evidence.

`node scripts/source.mjs --test core/tests/font.test.js` checks SFNT metadata with generated CC0 fixtures: Unicode name precedence, weight/style/width and variable ranges, table/name/axis offsets, overlap/version/count bounds, hostile byte-view shapes, source-byte isolation and unsupported/container/embedding refusals. `web/tests/static.mjs` separately loads static italic/oblique descriptors through the real browser font decoder and measures the synthetic glyph advance; metadata parsing alone is not font-program validation. Local system-font probes may inspect additional TTF/OTF/variable files without vendoring them, but are environment evidence, not portable fixtures or compressed-format acceptance.

`node scripts/source.mjs --test core/tests/font-upload.test.js core/tests/asset-upload.test.js core/tests/font.test.js` covers the shared allocator, byte/MIME/descriptor registration, one-step asset/CSS Undo, stale/concurrent/source/output collision refusal, CSS namespace/provenance and cache deletion/reopen. `node scripts/source.mjs --test core/tests/capture.test.js` proves font-only declared closure, exact MIME/bytes, conditions/descriptors, literal Data URLs, missing/dynamic/foreign-resource refusal, explicit payload reads and no source/revision/history change. `web/tests/snapshots.mjs` measures actual magenta synthetic-triangle pixels in the cached blob (the old fallback measured143px/2217 coloured pixels instead of120px/>3500), follows font-byte updates/Undo while retaining one iframe, holds an old font response across a newer render, refuses missing font proof and keeps stale/unembeddable captures live at far zoom. ## Format candidate

Run these from a source checkout:

- `npm run test:format`: Baseline for portable accepted/rejected JSON examples, normalization, project read/write stability, component addresses, plain CSS with no engine, the specification's example/tag lists and nullable override types. It also runs the reader audit as a regression gate. Type assertions are checked by `npm run typecheck`/`npm test`; Node's TypeScript stripping alone does not type-check them. This is not full standard conformance or a managed-HTML reverse-editing test.
- `npm run test:format:audit`: Standalone reader-boundary report. Its JSON identifies each input, the two readers' admission outcomes, project read/write stability and an unblocker when a retained invariant fails. It exits 0 on success or 1 on regression; runtime/I/O errors still fail rather than appearing as policy findings.

Fixtures live in `core/tests/fixtures/format/`, including a valid table and rejected context/paragraph/foster-parenting witnesses; every accepted frame's expanded static projection is checked. The baseline also checks exact override-metadata budget boundaries and preserved null-deletion/application-data semantics. `node scripts/source.mjs --test core/tests/model.test.js core/tests/codec.test.js core/tests/components.test.js` adds root/parent context and expanded-instance checks plus admitted simple-tree projection checks across all supported HTML tags. These bounded checks do not establish conformance for every possible tree or text value. The audit uses raw JSON value strings so numeric overflow is not erased by fixture serialization. These source-checkout tests are not installed package APIs. See [the candidate's evidence boundary](format.md#evidence-and-freeze-boundary).

The ordered CSS transition has a focused foundation gate: `node scripts/source.mjs --test core/tests/declarations.test.js core/tests/codec.test.js core/tests/format-types.test.ts`. It covers declaration order/fallbacks, first-position set/remove operations, property case, input isolation, legacy-map equivalence and shared serialization in the current codec. It does not establish the complete unfrozen schema-1 target profile or native cascade emission; those remain transition work.

The renderer requirement seam has a separate focused gate: `node scripts/source.mjs --test core/tests/engine.test.js core/tests/no-engine.test.js core/tests/format-types.test.ts`. It covers explicit native CSS with installed/absent providers, exact and order-independent selection, receiver/input preservation, missing/version/ambiguity/capability refusals, compiler-error propagation and unchanged omitted-requirement draft behavior. `node scripts/source.mjs --test plugins/tailwind/tests/renderer.test.js plugins/tailwind/tests/renderer-types.test.ts` adds portable installed dependency/stylesheet identity, nested-resolution and missing-installation refusals, exact descriptor typing and a hostile project-local stylesheet witness. The witness proves both pinned required compilation and retained ambient draft behavior. These do not prove project `requires` admission, matched resource/inspector capabilities, cache-independent required project rebuilds or engine-disable conversion; those remain integration work.

## Conventions

- Assert actual state (project file, model, accepted version), not only that a request returned.
- Client module boundary: `node scripts/source.mjs --test web/tests/modules.test.js` resolves literal static/lazy/re-export dependencies across the board and plugin client roots, refuses missing/TypeScript targets and checks their local graph for cycles. Runtime-computed specifiers are not parsed; plugin roots are enumerated separately. `features.mjs` also exercises two-artboard clipboard paste and one-step Undo, checking that facade lifecycle exports retain function identity; `controls.mjs` covers creation/reveal, duplicate, delete and toast Undo. `features.mjs` also checks a refused component library followed by an accepted unrelated deletion (correct success name, captured versions, visibility and one toast Undo), a held deletion racing a real peer edit (refusal preserves the peer frame/revision/undo depth), consumer-before-library multi-delete with one grouped restoration; and overlapping hidden/missing targets sending no additional request, preserving the first command's visibility reservation and peer edit. Toast Undo coverage is immediate/non-interleaved, not a command-specific inverse under arbitrary concurrent history.
- History traversal: `node scripts/source.mjs --test core/tests/history.test.js` covers ordered atomic multi-step Undo/Redo, grouped multi-frame movement, settings/content and frame lifecycle (including exact source/model frame order), external reorder-only and mixed membership/reorder transactions, retained frame-scoped selectivity, bounded counts and unchanged state/source/output/stacks on later conflicts, injected pre-publication refusal or real output preflight rejection. It does not simulate every filesystem fault or redefine post-source generated-cache recovery. The multi-step success witness counts one persistence call and one accepted revision per traversal; this core-only suite does not establish browser behavior.
- History points: `node scripts/source.mjs --test core/tests/history-line.test.js core/tests/history.test.js core/tests/safety.test.js` adds grouped-frontier invalidation, stable return IDs, one-write point jumps, no-op navigation, stale/queued requests, branching, selective/untracked boundaries with legacy Undo/Redo preserved, mixed lifecycle/order, refusal authority, the real 200-group window, HTTP reads, restart isolation and no source serialization. Audit-only events do not move the cursor; net-equal group replay can move it without advancing the audit sequence. These are core addressing checks, not evidence of clickable browser state rows or persistent history.
- History HTTP: `node scripts/source.mjs --test core/tests/server.test.js` checks owner-advertised `history.navigation`, whole-project timeline reads despite audit filtering, grouped movement/settings/lifecycle traversal with one persist and forward return, current-point no-op, actor projection, stale/unavailable/malformed refusals, Origin/token-prefix boundaries and real symlink preflight refusal preserving state/source/stacks. Two held HTTP requests prove expected-point rechecking inside the writer queue. SSE coverage observes a point-only move without an audit sequence change; monotonic runtime revisions are not historical state addresses. Browser row evidence is scoped separately below.
- History UI: the History block in `node web/tests/controls.mjs` exercises point rows, forward return, branch/future removal, point-only refresh with unchanged audit seq, Enter/Space, focus retention, Home/End, phone/200% text containment, read-only audit and owner-capability absence/return without navigation dispatch. Deterministically held GETs test both stale B and stale A-future snapshots arriving after A → B → A; matching current IDs cannot retain a discarded future. Hidden History must not fetch a complete timeline on every edit. Held HTTP-400 and missing-timeline responses after an owner change must expose no old addresses, make no automatic retry during a bounded 400 ms observation and recover with one read on reopen; these are preservation checks, not a long-duration outage/reconnect soak. `node web/tests/history.mjs` adds a real live pointer drag whose partial frontier disappears and whose single state restores source/model and actual camera-projected canvas wrapper positions/dimensions. It restores grouped multi-frame content/settings/tokens/CSS/create/delete/order as one persistence/revision; checks edited text in two surviving iframes and restoration of a non-tail deleted frame (explicit survivor reordering is covered by the core suite); refuses real output symlinks and held stale UI requests without an accepted prefix; recovers after safety repair; reconciles selective/untracked boundaries; retains IDs on browser reload but not owner restart; and renders the real 200-group window independently of the smaller audit window, traversing its earliest/latest endpoints in one persist each. `npm run test:history` runs its core/HTTP prerequisites and this acceptance suite. These bounded scenarios do not simulate every filesystem fault, an unbounded retry soak or referenced-resource byte restoration.
- Expanded viewing: `node web/tests/fullscreen.mjs` checks immediate site content without a second control, ordinary frames kept distinct from the site's template, native fragments/keyboard cross-frame links/linked HTML with external local CSS and images, the same iframe, desktop/phone viewports, opaque site live updates and fresh editor return. `node web/tests/security.mjs` also replays the pre-view capability from a navigated document and rejects it, retaining no-referrer/no-model-leak and trusted post-reset editing. `core/tests/server.test.js` checks the accepted-map public route, read-only nonce/CSP boundary and private/missing file refusal using real manifest-derived metadata names, while retaining sidecar repair. This does not certify the separate scaled-canvas Play navigation path.
- Preview links: `node web/tests/preview-links.mjs` checks that in Play a same-page `#fragment` or bare `#` link scrolls the preview without a navigation or a request for a missing `files/` path, an unknown fragment stays put and the authored `href` is unchanged. A `page.html#fragment` or `./page.html` link to another artboard reveals and selects it and scrolls its page (a plain page link lands at the top), a link to an unknown page is named in a toast, and no iframe navigates. Select mode still only inspects. A query string is ignored when naming the page. Site routes are not covered.
- Text-edit render hand-off: `node web/tests/text-edit-render.mjs` holds the render that follows a first text commit (`api/render`) until the second edit is open, starts that edit before the page has it, lets the render arrive while typing and commits. The edit must be accepted (no `RENDER_CONFLICT`) and the page must then show the text. It fails without the bridge naming the held render. It does not cover the key channel itself or toast timing.
- Native head: `node scripts/source.mjs --test core/tests/head.test.js` checks optional/strict description and icon fields, escaping, physical-head/manifest consistency, import, empty/absent distinction, merge/null/history and source-relative icon resource closure. It does not add arbitrary head content or external/absolute resource relocation to Save a copy.
- Landing: The canonical source is `examples/landing/landing.divlet`, with owned prepared output in `examples/landing/.divlet/landing/`. The Pages workflow checks that nested source/cache on Node.js 22 before copying the shared public set; npm publication remains a separate gate. `node scripts/source.mjs --test core/tests/landing.test.js` checks native source/codec round trips, relocated cache regeneration, provenance and private/unowned exclusions, stale inputs/assets, metadata-only fingerprint stability, copy collisions, head/fragment/resource closure and the CI copy contract. `npm run landing:check` independently refuses stale committed output without editing it. `npm run test:landing` serves only a dry publication copy under `/divlet/`, checks real fragment clicks and favicon loading at 1280/390/195 CSS px in light/dark, and saves screenshots. This is static-host evidence, not a fix for preview Play navigation or proof of a deployed site.
- Mark drawing: `node scripts/source.mjs --test web/tests/icons.test.js core/tests/landing.test.js` checks the separate bracket/D paints, matching diagonals and synchronized board/launcher/landing/favicon geometry, with no per-part alpha and unchanged self-contained landing ownership. `node scripts/source.mjs web/tests/chrome.mjs` verifies computed stroke/fill colours and a genuinely filled D interior; `native-collections.mjs` retains launcher/theme/zoom behavior. These checks do not publish the landing.
- Tooltip copy: `node web/tests/toolbars.mjs` checks full text, wrapping and no horizontal/vertical clipping for long prose and unbroken references at the viewport edges and centre, at desktop/phone/200%. Keyboard-triggered diagnostic headings also wrap rather than ellipsize. These checks do not remove the existing height budget for diagnostic code excerpts.
- Narrow sidebar chrome: `npm run test:chrome` drags the real edge to 240px, checks complete tab labels and separate icons/counts (including four-digit diagnostics), and compares open/folded label positions. Board/frame/node context headers must contain their text and stay clear of the prompt. `npm run test:fluid` repeats tab containment, context separation and logical-pixel density classification at phone/200%; `toolbars.mjs` retains keyboard, contrast and touch checks.
- Agent conversation: `npm run test:chat` checks a bottom-aligned short stack without overflow, chronological/reachable history after overflow, following new messages versus preserving an older reading position, returning to the bottom or sending a new request, fixed composer geometry, composer/activity resizing, folded-pane arrivals and explicit message focus at desktop, phone and phone/200%. It rejects interpreting a queued scroll from an old layout as a reader leaving the bottom. Footer geometry also keeps Send/Queue bottom-right without overlapping controls in selector, key-hint, enabled, disabled and disconnected states, including actual 240px edge resizing.
- Agent activity: `node scripts/source.mjs web/tests/agent-status.mjs` independently checks the folded spinner/timer/Stop footer alignment, full-width description, scrolling and original-node restoration at 390/820/1500px and 100/150/200%, with a working keyboard Stop. `node web/tests/features.mjs` checks the five-column/three-row grid, original-node identity across Agent/folded docking, a single Stop, busy starting while folded, keyboard stopping from either home, unchanged tab geometry and no idle shell. `node web/tests/fluid.mjs` checks remembered 240/480px desktop widths and phone/200% sheet widths, card/tab alignment, viewport bounds, actual Stop hit testing and inspector clearance. Long unbroken activity must scroll inside the bounded floating text area, not cover Stop/tabs; expanded browsing hides the footer and returning restores it. The in-pane grid retains readable live elapsed time and bottom-right Stop.
- Inspector ergonomics: `node web/tests/toolbars.mjs && node web/tests/fluid.mjs` checks one vertical flow with no duplicate section tabs, stale order-preference isolation, remembered native disclosures, Space/Enter activation without stealing canvas pan, and reachable/unclipped content at desktop, tablet, phone and 200% interface size. It retains toolbar resizing/overflow, focus-ring, contrast and touch-target checks. The toolbar selector witness uses real 280px resizing, the paired typography row at 320px, and phone/200% to check vertically centred labels/carets and whole single-line values. The layout-wrap suite also composes real Display/Position controls in the reported 246px row and verifies that they stack while their Default values remain whole; wider rows keep both fields side by side. The fluid suite also measures actual/default numeric text against usable input width in element/artboard views, not just wrapper overflow; `node web/tests/layout-wrap.mjs` adds positioned/Effects/typography fields and paired-control coverage across 170–320px containers at 390/768/1280px viewports. It keeps text alignment in Appearance and item alignment in Layout, with attached captions and independent keyboard edits. The appearance suite also verifies the moved control's single home, actual computed text alignment and one-step Undo. `node web/tests/spacing.mjs` additionally checks the four named position/margin/border/padding bands, eight independent spacing editors, canvas hover/focus, one undoable offset editor, signed measured margins, asymmetric borders, fractional content dimensions under both box-sizing modes and transforms, hidden/visible recovery and honest mixed states. Desktop/phone/200% geometry rejects colliding captions/values and horizontal overflow; canvas text metrics check complete authored and computed-only signed/fractional values, with extra band rows rather than clipping. Short-value screenshots retain the compact reference shape; long values may require inspector scrolling. `node web/tests/appearance.mjs` uses the actual resize handle to reach the 280px minimum, checks adjacent radius/border fields and Tab order, border/radius edit isolation, whole single-line weight options and readable two-column artboard bounds. The fluid suite also checks the radius/border pair at 200% phone UI size. `appearance.mjs` additionally drags real Effects labels: Z-index from implicit/explicit auto, signed integer steps, Shift acceleration, keyboard stepping, unchanged click/cancellation/capture-loss state, undo, mixed selection and 200%; opacity/blur keep their numeric defaults. - Importer plugins keep their tests beside them; a plugin's tests must pass without any other plugin installed.
- Screenshots go to the ignored `artifacts/` directory.

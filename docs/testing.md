# Testing

| Check | Command | Covers |
| --- | --- | --- |
| Unit | `node --test` | Model, project, codec, styles, runtime, server, launcher, import, history, safety, output ownership, static/site builds, the Pi adapter (`adapters/pi/tests`), plugins (`plugins/*/tests`) and package contents. |
| Browser (all) | `npm run test:browser:all` | The 25 real Chromium suites in `core/tests/browser/`: `run`, `responsive`, `layout-wrap`, `site`, `fullscreen`, `settings`, `interact`, `selection-completion`, `size-editor`, `controls`, `features`, `spacing`, `toolbars`, `appearance`, `reimport`, `chrome`, `fluid`, `snapshots`, `launcher`, `launcher-errors`, `native-collections`, `projects`, `security`, `static`, `native-default`. Most have a `test:<name>` script (`test:spacing`, `test:chrome`, …); `appearance`, `reimport` and a few others run only through this command or through a combined script (`test:controls`, `test:launcher`, `test:source`). |
| PEN fidelity | `npm run test:pen-fidelity [file.pen ...]` | Renders every root frame of a `.pen` (default: `examples/pen/field-notes.pen`, two frames) from the native projection and from the converted Divlet frame in Chromium and requires identical pixels; a flat, single-colour screenshot counts as a failure too, because an identical blank canvas would prove nothing. `PI_DIVLET_FIDELITY_LIMIT=N` samples the first N frames. The 68-frame, 3 195-instance result quoted in the changelog came from a design that is not part of this repository and cannot be reproduced from it. |
| Release | `npm run test:release` | Packs the package, installs the tarball into an empty directory and proves that the CLI answers, a board starts and serves the client and a plugin's client module, and the installed MCP server answers `initialize`, lists the shared tools and opens a board **without Pi**; the package holds no tests or caches. Executes the opt-in versioned compiler from the installed build, and also packs/installs `pi-divlet` against that product and checks it re-exports the same adapter function; this is not a real Pi session. Needs the npm registry (or its cache); publishes nothing. |
| MCP | `npm run test:mcp` | Spawns the packaged MCP entry and speaks its stdio transport for real: `initialize`, `tools/list`, tool calls with a domain refusal, two clients sharing one board (attachment, not a second writer), concurrent writes refused by revision, shutdown on EOF and board de-registration. |
| Contract | `npm run test:contract` | One tool list; the JSON Schema and TypeBox renderings agreeing on required parameters; the agent vocabulary; a board running only the tools it publishes; the board registry (one live owner, stale entries removed). |
| Pi RPC | `npm run test:pi` | A real Pi in RPC mode with a scripted model: a board request reaches a divlet tool, changes the project and returns as a reply. Skipped when the `pi` CLI is absent. |

## Format candidate

Run these from a source checkout:

- `npm run test:format`: Baseline for portable accepted/rejected JSON examples, normalization, project read/write stability, component addresses, plain CSS with no engine, the specification's example/tag lists and nullable override types. It also runs the reader audit as a regression gate. Type assertions are checked by `npm run typecheck`/`npm test`; Node's TypeScript stripping alone does not type-check them. This is not full standard conformance or a managed-HTML reverse-editing test.
- `npm run test:format:audit`: Standalone reader-boundary report. Its JSON identifies each input, the two readers' admission outcomes, project read/write stability and an unblocker when a retained invariant fails. It exits 0 on success or 1 on regression; runtime/I/O errors still fail rather than appearing as policy findings.

Fixtures live in `core/tests/fixtures/format/`, including a valid table and rejected context/paragraph/foster-parenting witnesses; every accepted frame's expanded static projection is checked. The baseline also checks exact override-metadata budget boundaries and preserved null-deletion/application-data semantics. `node --test core/tests/model.test.js core/tests/codec.test.js core/tests/components.test.js` adds root/parent context and expanded-instance checks plus admitted simple-tree projection checks across all supported HTML tags. These bounded checks do not establish conformance for every possible tree or text value. The audit uses raw JSON value strings so numeric overflow is not erased by fixture serialization. These source-checkout tests are not installed package APIs. See [the candidate's evidence boundary](format.md#evidence-and-freeze-boundary).

The ordered CSS transition has a focused foundation gate: `node --test core/tests/declarations.test.js core/tests/codec.test.js core/tests/format-types.test.ts`. It covers declaration order/fallbacks, first-position set/remove operations, property case, input isolation, legacy-map equivalence and shared serialization in the current codec. It does not establish schema-3/frame-2 admission or native cascade emission; those remain transition work.

The renderer requirement seam has a separate focused gate: `node --test core/tests/engine.test.js core/tests/no-engine.test.js core/tests/format-types.test.ts`. It covers explicit native CSS with installed/absent providers, exact and order-independent selection, receiver/input preservation, missing/version/ambiguity/capability refusals, compiler-error propagation and unchanged omitted-requirement draft behavior. `node --test plugins/tailwind/tests/renderer.test.js plugins/tailwind/tests/renderer-types.test.ts` adds portable installed dependency/stylesheet identity, nested-resolution and missing-installation refusals, exact descriptor typing and a hostile project-local stylesheet witness. The witness proves both pinned required compilation and retained ambient draft behavior. These do not prove project `requires` admission, matched resource/inspector capabilities, cache-independent required project rebuilds or engine-disable conversion; those remain integration work.

## Native HTML stabilization

`node --test core/tests/html-import.test.js core/tests/import.test.js` checks core-owned HTML admission without an HTML plugin registration, with no style engine, and through explicit `.html`/`.htm` opening, folder-page ingestion and re-import. It covers reported sanitization losses, preserved sources, existing destinations, listing policy, link refusal and unsupported input. It does not establish managed-cache reverse editing; generated-page hand edits remain diagnosed rather than imported.

## Conventions

- Assert actual state (project file, model, accepted version), not only that a request returned.
- Inspector ergonomics: `node core/tests/browser/toolbars.mjs && node core/tests/browser/fluid.mjs` checks one vertical flow with no duplicate section tabs, stale order-preference isolation, remembered native disclosures, Space/Enter activation without stealing canvas pan, and reachable/unclipped content at desktop, tablet, phone and 200% interface size. It retains toolbar resizing/overflow, focus-ring, contrast and touch-target checks. The fluid suite also measures actual/default numeric text against usable input width in element/artboard views, not just wrapper overflow; `node core/tests/browser/layout-wrap.mjs` adds positioned/Effects/typography fields and paired-control coverage across 170–320px containers at 390/768/1280px viewports. `node core/tests/browser/spacing.mjs` additionally checks the compact eight-field diagram, independent side edits, caption focus and M/P markers; fluid geometry checks reject overlapping fields, clipped captions and markers covering inputs at phone/200% widths. This is not a complete per-section design audit.
- Layout contracts are tested with geometry at 390 px, 390 px at 200% interface size and 820 px (`core/tests/browser/fluid.mjs` holds the 200% case; `chrome.mjs` holds the wide and phone layouts without it); errors and statuses must not move controls (`launcher-errors.mjs`, `projects.mjs`).
- Importer plugins keep their tests beside them; a plugin's tests must pass without any other plugin installed.
- Screenshots go to the ignored `artifacts/` directory.

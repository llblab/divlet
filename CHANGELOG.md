## Unreleased

- **Shared mandatory patch-version admission.** Frame/project patch paths in both writers now use one core-owned required-version guard, preserving their existing mandatory read-point checks, scope-specific errors/details and version/render/host/candidate ordering. Authored Node/Chromium guard vectors and real direct/tool-path refusals cover omitted/invalid/stale versions, frame no-ops and queued stale reads with retained state/source and persistence counts. Optional lifecycle admission, project no-op behavior and stored format are unchanged; no previously accepted missing-version bug is claimed.
- **Queued direct history regression coverage.** Entered-gate Node/browser scenarios now verify edit → Undo → Redo ordering, refusal of a discarded Redo future after branching, and replay of only accepted groups after a refused queued edit. Investigation did not reproduce the suspected stale-stack-reference defect: current producers mutate stable arrays in place. An isolated counterfactual array-replacement control makes the new active-stack oracle fail. No runtime behavior or writer authority changed; remaining writer coordination stays open.
- **One queued history-navigation decision path.** Node and browser share address validation and a readonly target planner for backward/forward/no-op decisions and unchanged stale/unavailable refusal precedence. Both writers validate addresses before reading their own timeline and resolve the expected point inside their queue, retaining actor, replay, persistence and stack/point authority. Authored Node/Chromium outcomes, type guards and real-writer queue/no-op/refusal witnesses cover the seam. No new history wire data, host capability or installed browser SDK is introduced; accepted-state/commit coordination remains open.
- **One read-only history traversal planner.** Node and browser now share group selection, frame-scope filtering, step validation, label choice and pre-reversal composition order through `history.ts`. Plans retain original entry identity and whole-group payloads; descending indexes are consumed only by the writer after preparation/persistence succeeds. Frozen-input, bounds/refusal, typed-payload and real replay-composition witnesses run in Node and native browser ESM. Queues, source/output authority, stack/point mutation and host failure policies remain unchanged; this does not complete writer extraction or change history wire data.
- **One history replay candidate kernel.** Node and browser writers now call the same typed, host-independent item replay for guarded content/project patches, frame lifecycle slots, relative order and endpoint version coalescing. Immutable-input vectors cover forward/reverse grouping, no-op identity, conflicts and invalid late patches, with the same cases executing in real Chromium imports. Each writer retains whole-project preparation, its persistence/failure policy, accepted-state publication and stack/point authority. Parity edits now use a stable authored fixture and assert success versus named refusal explicitly, fixing a false-positive path where stale landing IDs made both writers refuse; canonical landing rendering remains separately checked. No new wire format, browser host capability, public SDK entry or ordered-style semantics are introduced; remaining writer orchestration stays open.
- **Preserve unreplayable live source styles.** External JSON edits now check native literal/override style sequences through actual forward and inverse merge patches before accepting their source hash. Order-only edits previously looked unchanged and a later unrelated edit could overwrite the authored order; value/order changes, inverse-lossy removals and stored-null operations could also lose style meaning through history. Such live transitions now refuse with `UNSUPPORTED_STYLE_REPLAY`, preserving authored bytes, accepted output, selection and stacks while the pending-source guard blocks writes. Representable changes and fresh opens retain existing map behavior. This is a conservative safety boundary, not order-aware generic equality, a new reader profile or complete ordered-style history.
- **PEN importer honors plain byte views.** Claims, conversion and summaries now decode the actual `Uint8Array` window rather than calling Buffer-only string conversion. Plain Uint8Arrays, offset subarrays and Buffer inputs share the existing UTF-8 replacement and JSON error behavior; leading BOMs remain refused rather than silently stripped. Byte/coercion/state regressions and a compiled-public probe guard the runtime contract, including the package test's post-build public entry. No native reader, foreign wire version or source bytes are rewritten.
- **Refuse lossy PEN inline-style linking.** Conversion now checks each linked candidate through real core expansion against the pre-link projected element/inline-declaration sequence before serializing. Direct and nested component linking that would change CSS order/values refuse with `UNSUPPORTED_PEN_RENDER`; representable value edits keep their links. Previously accepted order-changing cases could render a different shorthand/longhand cascade. Refusal preserves foreign bytes and publishes no native candidate. The tested ordinary legacy `.divlet` failure path restores its original location without backup residue; existing recovery can retain the moved source if filesystem failure or concurrent path occupation prevents restoration. The draft map representation and readers are unchanged; ordered conversion support remains FORMAT-TRANSITION work.
- **Context-aware component attribute peers.** Attribute-operation layers now resolve against the final consuming HTML/SVG namespace after enclosing tag overrides. Equal HTML case aliases coalesce, conflicting canonical sets/deletions refuse, and explicit outer writes retain layer precedence without hiding lower peer conflicts. Canonical edits replace/remove lower name spellings while stored override spelling stays intact. Untouched duplicate-normalized names and final placement/unsafe/resource guards remain authoritative. Shared reversed/retag vectors, actual browser label/SVG contexts and selected-writer refusal/Undo/Redo regressions cover this bounded slice; ordered styles, general reference closure and arbitrary SVG HTML round trips remain separate work.
- **Acyclic style capability contracts.** Transient style input, lowering options and exact renderer-selector types now live with the provider-free style contract; model/engine public type names and persisted vocabulary remain compatible. The registry no longer imports the semantic model even for types, and the browser lowering port names the registry rather than default composition. A model-absent ES-only single-file typecheck guards the erased dependency boundary. Runtime statements/default selection are unchanged; the bounded core/plugin source graph is now acyclic. Packaged public native-only composition remains separate work.
- **Consumer CSS/token scope evidence.** Shared expansion and compiler-port tests, five actual browser cascade contexts with Node-prepared HTML parity, and writer edit/Undo checks establish the existing consumer-scope contract. Reused class references and inline expressions survive; project/consumer styles and tokens supply context, while source-only styles/tokens and outside ancestors do not travel. Source-only edits retain consumer output and selected linked identity. No production styling behavior, dependency selection or stored format changed.
- **Frame-scoped DOM ID uniqueness.** The native validator now refuses duplicate nonempty canonical DOM IDs, including component-occurrence collisions, without renaming IDs or references. Empty IDs, exact case/Unicode identity and independent frame namespaces remain supported. Shared Node/Chromium vectors, real label/ARIA/SVG reference witnesses, dependent-frame writer refusal/Undo checks and visible UI duplicate refusal cover the boundary. Successful duplicate-selection timing cases use native instrumentation identity rather than accidentally authored DOM IDs. This does not add general reference closure or change the stored schema/ID grammar.

## 0.0.1 — 2026-11-13

Published `@divlet/web`, `@divlet/core`, `@divlet/cli`, `@divlet/mcp` and `@divlet/pi` on npm with matching versions and verified archive integrity. Clean registry installations exercise the standalone board, CLI/MCP tools and an isolated real Pi host.

Initial release of divlet: a local HTML/SVG/CSS layout board for agents. The native project format remains an unfrozen schema-1 draft; this release does not activate the approved future ordered-CSS/renderer profile or promise frozen compatibility.

### Product and agent integration

- **One product, three real adapters.** `@divlet/core` supplies the model/runtime/server, bundled plugins and portable workflow skill. The separate `@divlet/web` owns the only browser client and portable host ports, without a core/Node dependency; the HTTP composition uses its public asset locator. `@divlet/cli`, `@divlet/mcp` and `@divlet/pi` own their commands and implementations, with exact matching core dependencies; core pins web. All five release versions match. CLI/MCP/Pi own their real packages directly in `cli/`, `mcp/` and `pi/`, beside core and web; workspace, build, source/installed entrypoints and documentation follow the flat topology without wrappers. The unscoped `divlet` npm name was refused by registry policy; the product, command and tool identities stay divlet. Node.js 22.19 or later is required; CLI and MCP do not require Pi.
- **Seven shared validated tools.** Pi and MCP use the same open/read/patch/structural-edit/frame/history/work-mark contract, revisions and refusal codes. Board requests carry the submitted selection snapshot and compact context rather than following later selection changes. MCP sampling and Pi model/thinking controls appear only when the host advertises them; session settings are not project content.
- **One live writer per project.** Other clients attach to the owning board and share its revisions and history. Importing the library or an adapter starts no service. Installed packages use compiled exports; checkout development runs TypeScript sources without a build.

### Native projects and files

- **Real web content in independently owned files.** A `.divlet` contains frames, shared tokens/CSS, reusable components, property overrides and inert metadata. Valid external edits are accepted; invalid or stale candidates preserve the last working state. Discovery and the launcher distinguish exact project files, including same-named projects.
- **Bounded HTML admission and foreign-format conversion.** Static HTML imports use the core sanitizer; PEN interpretation belongs to its importer plugin. Conversion creates a non-overwriting sibling project and preserves the original. Markdown sites retain routed pages and shared templates.
- **Embedded resources with explicit identity.** Image uploads and declared files retain their bytes in a hierarchical Data-URL asset tree, materialized only as rebuildable output. Explicit `asset:` references preserve names, MIME and dependency bases; literal Data URLs stay inline. Existing filesystem inputs remain supported without silent absorption.
- **Owned static output and export.** Generated HTML/resources have per-project provenance, collision/link refusal and repairable sidecars. Supported local dependencies survive portable publication below a URL prefix. Clean per-frame HTML export embeds supported resources; ambiguous query, SVG-use, cycle or expanded-size semantics refuse rather than silently change meaning. Save a copy creates an independently identified project.
- **Device fonts use ordinary CSS and common assets.** Family selection preserves understood fallback stacks and inline priority. TTF/OTF, bounded WOFF 1 and restricted null-transform WOFF2 registration retain exact submitted bytes and append only proven disjoint companions. Upload and selection are separate Undo steps. Static CFF2 and independently encoded CFF1 WOFF fixtures exercise actual browser matching and portable loading.

### Board and editing

- **Long-lived live artboards.** Lazy iframes retain identity through edits, zoom and selection. Expanded browsing is separate from authenticated editing; known page/fragment links reveal their artboards, and projected missing-page links report the unsupported destination. Browser-generated snapshots embed proven font bytes; stale or unprovable captures keep the live page instead of showing fallback-font text.
- **Direct, responsive inspection.** Layers, bottom breadcrumbs, one vertical inspector flow and adaptive toolbars expose layout, typography, appearance and metadata. Spacing uses outside-in box bands with independent side values and measured content dimensions. Border has two synchronized views and one writer. Controls retain whole values, keyboard access and useful narrow/200% layouts.
- **Guarded whole-project history.** Grouped and multi-step Undo/Redo validate the complete candidate, refuse overlapping later edits and persist before moving stack authority. Frame lifecycle/order replay preserves authored positions. History state points name proven stack endpoints, not audit sequence numbers.
- **Stable conversation and feedback.** The agent pane follows arrivals near the bottom without stealing older reading positions. Activity/Stop moves as one surface when the sidebar folds. Delayed agent-start notices defer for a bounded interval to preserve the ordinary Undo window, and deleted artboards no longer publish queued measurements.

### Safety and boundaries

- **Local, bounded access.** The board binds to loopback with token-scoped routes, Host/Origin checks, CSP and request bounds. Filesystem operations use regular-file/no-link checks, byte/count budgets and non-overwriting publication. Trusted project access is not an arbitrary HTTP filesystem route.
- **Authenticated previews.** Editing traffic uses a current document-bound MessagePort with capability rotation, sandboxing and referrer protection. A matching iframe window alone is not authentication. Stale observations, captures and async reads cannot replace newer accepted state.
- **Explicit current limits.** Arbitrary application scripts, managed-HTML reverse editing, an offline browser writer and automatic public-safe snapshot curation are not implemented. Transformed WOFF2, font collections/optional container blocks, ambiguous face merging, wider linked/imported/dynamic font capture and native external SVG-use remain refused or gated. Variable CFF2 and arbitrary font-program compatibility are not established by static fixtures.
- **Separate evidence layers.** Source/unit/browser, local installed-tarball, registry-install, static-host and format-freeze evidence are distinct. Strict Node/core types and a small checked client transport slice do not imply whole-client typing. The portable browser semantic slice is not a complete offline editor.

Pre-release implementation and retired-experiment history remains in Git. See [testing](docs/testing.md) for executable checks and their coverage limits; future work is tracked only in the backlog.

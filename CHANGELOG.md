## 0.3.1 — Unreleased

- **The Border frame, finished.** The four corner radii moved out of the frame, above and below its corners, so none covers a
  side; the radius and the colour for all four sides never step out of the cut-out any more, because it always fits them (the
  cut-out is measured from the padding band, exactly the band's size). A one-pixel seam in the box model band's own line now
  separates the four colour trapezoids. The unit button on the right of a number is its own tinted area and no longer ends in a
  `▾` glyph, and its colour is a background rather than blue text. The tab order is the reading order
  (`web/lib/properties.js`, `web/board.css`, `web/tests/appearance.mjs`, `web/tests/fluid.mjs`, `web/tests/toolbars.mjs`).

## 0.3.0 — Border frame, unit menus and a steady box-model axis

- **Border is a picture frame of colour selectors, cut like the band it copies.** The Border control is the box model's border
  band at its own measured outer size with the padding band's measured place cut out, divided on the diagonals into four
  trapezoids; each is the colour selector for its side and is painted in that colour. Each corner carries its radius with a
  unit menu, and the cut-out holds one radius for all corners and one colour for all four sides (written as the four side
  longhands). A unit typed into any unit-menu field (`100%`) moves to the clickable accent-coloured unit button on its right,
  a bare number takes that unit, the menu changes only the unit and keeps the number — no conversion, for the line height too —
  and `full` has no unit.
  The four edge widths stay out of Border: a width has one home, the four sides of the box model's border band. The box
  model's band names became out-of-flow watermarks, so every top value now sits on the same axis as its bottom value
  (a band too narrow to hold its name beside that value gives the name up rather than cover it)
  (`web/lib/properties.js`, `web/lib/css-props.js`, `web/board.css`, `web/tests/appearance.mjs`, `web/tests/spacing.mjs`,
  `web/tests/toolbars.mjs`, `web/tests/css-props.test.js`).

## 0.2.0 — Inspector and history polish

- **The interface measures itself in layout pixels.** At 200% the action row reported every action as twice its real width
  and kept only one plus the "more" menu, and the inspector's shared label column asked for twice the room it needed, so the
  Phone/200% `Fit height` action was reachable only inside the overflow menu. The chrome is drawn under
  `transform: scale(--ui)`, so a painted width is a layout width times the scale: the toolbar's fit and the label column now
  measure with `offsetWidth` (`web/lib/toolbar.js`, `web/lib/properties.js`, `web/tests/chrome.mjs`,
  `web/tests/appearance.mjs`).
- **A version is read once the runtime's queue has drained.** The appearance witnesses took the frame's version while
  the board's own accepted edit was still queued and were refused as stale; they now drain the queue first, which is what
  "the current version" means for a shared writer (`web/tests/appearance.mjs`).
- **Two more witnesses wait for the state they assert.** The action bar's count is read only after the board restores its
  selection, and an inspector action whose row re-fits under the pointer is taken from the overflow menu the way a person
  would (`web/tests/toolbars.mjs`, `web/tests/controls.mjs`).
- **A band's name and its top value share one row.** At phone/200% the box model's watermark could reach the centred top value
  by a pixel and, on a different font stack, cover it. The name and that value now sit in one flow row inside the band — the
  value centred in what the name leaves — so no width or font can make them collide; long values keep their whole cell
  (`web/lib/properties.js`, `web/board.css`, `web/tests/spacing.mjs`, `web/tests/appearance.mjs`).
- **The browser battery checks the contracts that exist now.** The Play witness expected a leaving link to navigate the
  preview frame; it now proves the board's own window opens it while the frame stays on its page. And a far-zoom font capture
  whose frame is deleted mid-flight answers 404 — the board has already aborted it — so only that exact case stays silent,
  with each tolerated id checked against the frames that still exist (`web/tests/security.mjs`, `web/tests/features.mjs`).
- **The token row explains itself.** The `--color-brand → bg-brand, text-brand` caption under the Tokens add row is gone: the placeholders say what
  the two fields take, and the row no longer repeats it (`web/lib/inspector.js`).
- **Box-model side values keep their distance.** The left and right values sat flush against their band's frame and read as part of the line; they
  now keep one pixel of air from it, and the row they take on a narrow panel keeps the width that air would have cost (`web/board.css`,
  `web/tests/spacing.mjs`).
- **The history marker leans to its text.** In the history list the marker and its badge are right-aligned in their narrow column instead of
  centred, so the marker sits next to the change it belongs to and the column reads as one edge against the text (`web/board.css`,
  `web/tests/history.mjs`).
- **Labelled rows line up.** Rows that belong to one group now share a label column measured from the widest label in that group, so
  `Center` and `Self` in Layout start their controls on the same line, and the two centring choices fill the width their label leaves
  (`web/lib/properties.js` gained `syncLabelColumns`, `web/lib/inspector.js`, `web/board.css`, `web/tests/appearance.mjs`). The border
  ring's side menu is now its own value-named button rather than the caption-plus-value selector component, which it was never
  (`web/lib/properties.js`, `web/board.css`).
- **History rows give their width to the text.** The Restore / Current / Ahead badge moved out of a column of its own and now stacks under
  the marker inside the one narrow left column, so the change, its document and its actor get the whole remaining width to read in
  (`web/lib/activity.js`, `web/board.css`, `web/tests/history.mjs`).
- **History rows read again.** A row's document, actor and change detail no longer sit in the 44–80px marker column, where a long document
  name became a paragraph squeezed into a strip; the marker keeps its own narrow column and those details read under the change in the reading
  column, wrapping only where there is width for it (`web/lib/activity.js`, `web/board.css`, `web/tests/history.mjs`).
- **The Border block is the band, cut open.** The copy of the box model's border band lost its caption, is centred in its section so it sits on the
  same axis as the band it copies, and has its middle cut away to the panel's own surface where the widget above shows a content band; a radius sits
  in each corner, a width at each edge's centre and the colour inside the opening (`web/lib/properties.js`, `web/board.css`,
  `web/tests/appearance.mjs`, `web/tests/fluid.mjs`).
- **A link is editable and clickable.** The inspector gives an anchor its own **Link** section beside the element's name — the address, and a
  **New tab** control that writes `target="_blank"` with `rel="noreferrer noopener"` and takes back exactly what it wrote, while an emptied address
  removes `href` rather than keeping a link to nowhere; double-clicking a link with no words of its own lands in that field. In Play, a link that
  leaves the project (`https:`, `mailto:`) is now followed: the frame stays sandboxed without popups or top navigation, so the board opens the
  authored address from the visitor's own click, resolved in full and with its opener cut (`core/lib/bridge.js`, `web/lib/canvas.js`,
  `web/lib/inspector.js`, `web/tests/features.mjs`, `web/tests/preview-links.mjs`). The landing's footer names the GitHub repository as a real link
  instead of plain text that reads like one (`examples/landing/landing.divlet`, regenerated cache).
- **The board names its release.** Settings carries one quiet caption beside its title — `v0.1.2` in the faint tone, with the full release in its tooltip — read from the board state rather than from a second copy of the number: the local host reads its own package manifest and the static site passes the version its bundle was built with, so a published page can never claim a release it is not (`core/lib/version.ts`, `core/tests/runtime.test.js`, `web/tests/settings.mjs`, `web/tests/pages.mjs`).
- **The geometry block keeps no swap button.** Rotating an artboard already lives in its own ⋯ menu and in the palette's Rotate, so the extra icon at the end of the width chips — whose tooltip read “Swap width and height” — is gone, and the size chips end where the width presets end (`web/tests/controls.mjs`).
- **Every icon paints at one size.** The glyphs had drifted apart — `parent`, `play`, `send`, `trash`, `copy` and others sat around 11 units while `tidy`, `keyboard` and `component` reached 15, so a row of them read as a decreasing series; four glyphs (`gear`, `pencil`, `layers`, `child`) drew outside their own box and were clipped. Every glyph now paints at the same optical extent (~13.8 of the 20-unit box) with its own shape repaired, the brand mark keeps its authored geometry, and a caret, tick, close cross and stop square stay deliberately lighter. Chromium checks the painted extent of every glyph in the chrome, not its box (`web/tests/chrome.mjs`, `web/tests/icons.test.js`).
- **Expand points in four directions again.** The glyph had shrunk to two opposite corners; it is now four arrows out of the centre, each with its bracket in the outer corner, so a collapsed frame reads as the square its viewport occupies — and collapse stays the same four arrows turned inward, which reads as the way out of that view (`web/tests/icons.test.js`).
- **Overflow is a Layout selector.** Visible, Hidden, Clip, Scroll and Auto sit beside Display, read from both axes as one value — `Mixed` when only one axis is authored, instead of guessing the other — and written as `overflow-*` with Tailwind or one shorthand declaration without an engine, one Undo step each. The Tailwind provider now reads `overflow-*` back, including the axis utilities, so the selector shows what the class list already says instead of Default (`plugins/tailwind/tests/view.test.js`, `web/tests/features.mjs`, `web/tests/static-styles.mjs`).
- **The box model keeps its names outside the diagram.** The four bands no longer write `position`, `margin`, `border` and `padding` inside their own rectangles: one legend under the widget lists the layers in nesting order, each name in the tone its band used, beside a swatch of that band's own fill. Every band therefore keeps its whole rectangle for values, and the corner radius moves to a row of its own once the diagram's bottom edge can no longer spare the room (`web/tests/spacing.mjs`).
- **Effects follows Appearance.** The inspector's section order now reads Layout, Spacing, Border, Appearance, Effects: typography and colour sit together with the surface they shape, and opacity, Z-index and blur follow them (`web/tests/static-styles.mjs`, `web/tests/toolbars.mjs`).
- **Buttons read as buttons, and no line divides a section.** A dropdown selector and a segmented group carried the same fill as the input beside them, so Display, Justify or Style looked like a field you could type in; action controls now take their own surface one clear step deeper than a field's (`--control` / `--control-hover`, both schemes) and keep it on hover, with the tone doing the work instead of a border. The palette's search and footer, the settings dialog's blocks and its action row no longer draw separator hairlines — the rhythm of the space between them is the divider (`web/tests/toolbars.mjs`, `web/tests/settings.mjs`).
- **The chrome appears at once; only the canvas waits.** The chrome is built by the client — every icon, label and tool — so showing it before that module ran was showing the interface without its parts; hiding it until the first artboard preview had painted kept the whole board waiting for the slowest thing on screen, which made every start feel longer than it was. The start now has two halves: the chrome is shown the moment the client has built it, while the canvas alone keeps its own surface and one quiet spinner until its first preview paints, with an expanded page, an empty board or a failed start revealing at once and an 800ms cap keeping a single slow frame from leaving a plain surface (`web/tests/chrome.mjs`, `web/tests/pages.mjs`).
- **The line height's unit is a menu, and it opens on percent.** `%`, `em` and a unitless multiple are one measurement — all three are the element's own font size — so the unit button beside Line height rewrites the same value in whichever spelling the author wants (`24px` ⇄ `192%` ⇄ `1.92em` ⇄ `1.92`), converting px against that measured size and writing the result as one normal, undoable edit. A bare number below 10 stays the multiple it reads as; at or above 10 it is a percent written without its sign, so `150` means `150%`. The colour field's label reads Bg rather than Fill, and each field's unit button shows what is authored instead of a fixed caption (`web/tests/appearance.mjs`).
- **The inspector's action row opens with Expand, and Delete is red where it stands.** The selected artboard's lower action row starts with the same Expand as its heading — the heading's copy is the first control a narrow frame gives up to its ⋯, so the row is where it always is — and the row's own overflow keeps Expand until last, moving the rest into its trailing dropdown. Delete reads in the danger tone at rest, exactly like the same entry in a dropdown, instead of only on hover. The box-model radius field keeps the widget's standard compact field height (`web/tests/toolbars.mjs`).
- **A text size is read once, and line height has a control.** A hand-written `text-[12.5px]` was read as a *colour* named `12.5px`, so the size appeared in the colour field as well; a bare bracket is now a size when its value reads as a length, and the colour field stays empty. Appearance also gains a line-height field beside size and weight — a multiple, px/%/rem/em or `normal` — which lowers to `leading-*` steps and arbitrary utilities, reads back what the page author wrote (`leading-6`, `text-sm/6`) and stays a native declaration without an engine (`plugins/tailwind/tests/view.test.js`, `web/tests/appearance.mjs`).
- **The corner radius lives in Border's own corners diagram.** One custom block replaces the four identical width rows: the four corner radii sit in their corners, the four edge widths between them, and a shared value at the centre applies to every corner at once — px, %, rem, em and `full` in all five, a bare number read as px, one Undo step per edit. Writing one corner leaves the others as the class list wrote them, and the provider now splits a shorthand radius into per-corner utilities and reads them back. The box model keeps no radius field, so the radius has one home (`web/tests/appearance.mjs`, `web/tests/spacing.mjs`, `web/tests/fluid.mjs`, `plugins/tailwind/tests/view.test.js`).
- **The box model keeps its names where they were.** The bands name themselves again as watermarks in their own left corner, and the `px` marker in the widget's top-right corner is gone: every number in the diagram is pixels unless it says otherwise (`web/tests/spacing.mjs`, `web/tests/toolbars.mjs`).
- **Each history line is one time point.** The kind marker no longer leads the row: it sits with the line's metadata in a single narrow left column, the change reads beside it, and the elapsed time is gone — the list is a sequence of states, not a feed of events. The column narrows on a phone instead of squeezing the message (`web/tests/history.mjs`).
- **History lists the states you can return to, oldest first.** The list is no longer an audit log of every change: it holds exactly the states a restore can reach, opening with the boundary of the oldest one, ending the reachable past at the current state and showing the superseded future below in a dimmed tone — dimmed because the next edit may overwrite it, still selectable because it is a real choice until then. Changes that are not an addressable state are no longer rendered at all, and Home/End follow the new order (`web/tests/history.mjs`, `web/tests/controls.mjs`).
- **A colour name opens the picker instead of pretending to scrub.** The label of a colour field was styled like a numeric drag handle but had nothing behind it; it now shows a click cursor and opens the same picker as the swatch, while a drag on it writes nothing. Only labels that really scrub (numeric fields) keep the sideways-arrow gesture, so a caption such as Center no longer advertises one either (`web/tests/appearance.mjs`).
- **The box model names its bands as watermarks and centres its side values.** `position`, `margin`, `border` and `padding` sit in their band's top strip as larger type in a darker tone of that band's own fill, 12px in from the left; on a band too narrow for that they move closer to the edge and shrink, never covering a centred value. Left and right values are centred in their own strip instead of against the inner corner, which needed the strip to be measured in the value's own pixels rather than in `ch` of the band's font (`web/tests/spacing.mjs`).
- **A colour follows the picker while it is dragged.** The value field shows the picked colour at once and the page repaints within one write, instead of waiting for the dialog to close; typing a colour does the same after a short pause. A gesture stays one Undo step, and a fast drag keeps at most one write pending, so the page converges on the colour last picked rather than replaying a queue (`web/tests/appearance.mjs`).
- **A colour control is one row again.** Label, swatch, value and clear sit on one line in Border and in Appearance, and only a value longer than the room left takes a line of its own without being clipped. The content-sized value field was taking the wrapper's full width as its flex base, so it claimed a line by itself and pushed the clear button onto a third. Fill and Text now stay paired only while each field can still hold its own parts on one line (148px each) and otherwise stack whole, instead of squeezing both into a three-line column (`web/tests/appearance.mjs`).

## 0.1.0 — Native CSS controls and Tailwind in the browser board

- **A rebuilt landing, styled with Tailwind utilities only.** The headline spans the page, with the pitch and calls to action beside the agent/board transcript of one edit; four cards say what divlet is; how a change lands reads as four steps in a row; the CSS → Tailwind flow and the guided tour (two columns, no duplicate cards) follow; install is three wide rows whose commands never break inside a flag; the seven tools are grouped by job; formats sit beside the honest boundaries; a closing call ends the page. Every element is styled with utilities — the frame CSS only defines the light/dark palette the project's colour tokens point at — so selecting anything on the board shows real classes in the editor.
- **The website opens on the landing, not a preloader.** The Pages `index.html` paints the prepared landing (`page/index.html`) in a full-window cover before any script loads; the board starts behind it and only adds "Edit on the board" on top. The cover stays while the board shows that same unchanged page and goes on collapse, any change, a restored browser copy, a remembered canvas view or a failed start (`web/tests/pages.mjs`). Focus tips now follow keyboard use, so the first visit shows no tip over the page.
- **Every inspector style edit takes one path.** Per-edge border widths, the box model's content size, Family and More CSS no longer force inline CSS: with the Tailwind engine they are utilities like every other control (`!important` as Tailwind's `class!` modifier), without an engine native declarations. CSS custom properties always stay native declarations. A one-value arbitrary shorthand such as `[border-width:3px]` now splits into the sides an edge edit leaves, and an authored class such as `font-lock` is no longer mistaken for a family utility.
- **Tailwind edits replace the classes they compete with.** A property edit now removes every unconditional utility that set any part of that property — named ones such as `leading-tight`, `uppercase`, `gap-x-4`, `max-w-md`, `overflow-y-scroll`, `border-red-500` and `-mt-2` included — instead of leaving them to win the cascade, and splits a utility that set more than the edit (`size-4`, `inset-0`, `gap-4`, `rounded-t-lg`, `text-sm/6`, `overflow-hidden`) so its other parts survive. Edits are written idiomatically where a utility says exactly the same thing (`uppercase`, `italic`, `border-dashed`, `gap-y-1`, `leading-6`, `-mt-2`, `w-1/2`, `text-white`, `tracking-[…]`). The static board's agent instructions now say that utilities compile in the page.
- **Artboard headings fit their artboard.** The name, size, Expand and ⋯ More controls keep a readable size at any zoom and never extend past the artboard on screen. When room runs out, Expand moves into the More menu first, then the size and name are cut, with ⋯ sitting on the cut (`web/tests/toolbars.mjs`).
- **A cached website never mixes publications.** The Pages shell stamps the host bundle, the landing cover, the project and its styles with one publication hash, so a page served from the ten-minute HTTP cache cannot open an older project behind a newer landing.
- **The website remembers its last view.** A visitor who left for the board comes back to the board, with only the spinner while it starts; a reader who stayed on the landing (or expanded it again) gets the landing as the first paint. Previously the camera fitted on a first visit was mistaken for a choice of the board, and the landing flashed before the editor replaced it.
- **A plain spinner while the board starts.** The animated mini-board preloader is replaced by one small spinner that fades in only if starting takes long enough to notice.
- **Opaque editor chrome.** Pills, tabs, the dock, the crumbs and the expanded-page bar no longer use a translucent, blurred background, and the search pill stays opaque on hover.
- **A symmetric box model.** Long left/right values widen both side bands of their layer alike instead of stacking rows into the top band; only values too long for a side band (or any long side in a narrow inspector) take a row, with equal top and bottom heights.
- **Tidier inspector and History.** The border color field is one row like Fill and Text, the inspector says "color", the font family control drops its cascade note, and the History footer is one line of counters with feedback below it only while there is something to say.
- **The published skill command works.** `npx skills add llblab/divlet --skill divlet` against the public repository installs a copy identical to `skills/divlet/` (checked in a throwaway project, not a global profile).
- **A focused README.** The root README is an entry point — what divlet is, the website board, quick start, agent setup, tools and boundaries — with installation variants, package roles and compatibility details left to the agent guide.
- **Rework the landing page.** The canonical landing gains a board preview, a "Plain CSS first. Tailwind where it fits." section built from live utility-styled elements (so selecting them on the board shows real property values and class chips), refreshed copy and project colour tokens backed by the page's own variables, so utilities follow the colour scheme. The prepared build and its public fingerprint are regenerated through the normal owner.
- **Link typed utilities and inline declarations.** Adding a class through the class editor removes the inline declarations it would lose to (a covering shorthand is expanded first so its siblings survive) in the same accepted edit, and an explicit "Move inline declarations to classes" action rewrites plain inline CSS as utilities, keeping what no utility can express as CSS. Property controls and the class editor now read one authored meaning in both hosts.
- **Run Tailwind inside the static board.** The Pages build bundles a portable Tailwind provider (compiler, declaration ↔ utility lowering, class explanation and suggestions) from the renderer source captured at build time, serves the class editor as `plugins/tailwind/*` and reaches class knowledge through a new optional `BoardClasses` host port. A utility absent from the prepared snapshot now compiles in the page and reads back into the controls with no Node backend, route or remote compiler; the build can also compose a Tailwind-omitted board for native-only acceptance (`web/tests/static-styles.mjs`).
- **Move the property controls into the core client.** Layout, Spacing, Border, Effects and Appearance no longer disappear without the Tailwind panel: they read the element's inline declarations plus any registered style reader and write `styles` patches through the shared writer queue, so the static board edits CSS with the full control set. The Tailwind plugin keeps the class editor and a class-to-declaration reader. The raw CSS list (now "More CSS") shows only declarations no control owns, so a font or padding is not listed twice.
- **Make `styles` patches native CSS edits.** Without a style engine a `styles` patch writes ordered inline declarations (an existing declaration keeps its slot for replay, a longhand with a later covering shorthand expands it first, removal expands the shorthand that set it) instead of refusing with `NO_STYLE_ENGINE`. With an engine, inline declarations that would defeat the generated utilities are released first, and a property that cannot be released stays native. Tailwind lowering now also produces named spacing/`z-`/`opacity-`/`blur-`/`grid-cols-`/font-weight utilities, `mx-auto`-style axis margins and negative offsets.
- **Browser resources, export and preview lifecycle.** Optional trusted resource policies, closed preview projection, resource-aware element/page export, retired preview URLs, preserved browser copies on refused startup and the portable asset/MIME/carrier/SVG/declared-graph modules behind them. Default Pages stays closed to byte assets; see the foundation list below.
- **One history and acceptance path for both writers.** Shared commit, traversal, navigation, replay-candidate and patch-version admission code, nullable and node-lifecycle history, lossless ordered style history and replay-proven live source acceptance.
- **Format foundations for the first freeze.** Opt-in ordered declaration admission, structural renderer requirements, a native JSON text profile, frame-scoped DOM ID uniqueness and executable CSS-migration witnesses, with schema 1 unchanged.
- **Provider-neutral core.** The public `@divlet/core/native` host, provider-free style/importer registries and a model that loads with no provider port remap, with the Tailwind and PEN plugins as optional providers.

### Foundation work since 0.0.5

- **Keep source assets separate from native image services.** The optional browser composition now advertises `sourceAssets` while keeping the legacy image-service flag false. Clipboard/device image paste and inspector picker/upload/filesystem-thumbnail paths require the built-in native host, so capability data alone cannot dispatch unsupported HTTP routes. Alternative inspectors retain source references without guessed native thumbnails; literal thumbnails and native drop/upload/gallery behavior remain intact. Real consumer regressions reproduce the previously missed native POST/build-URL attempts and verify source/IndexedDB retention, absent controls and no fallback, including permissive metadata. This corrects the private composition's earlier capability mix-up; default byte gates and selected-node export remain unchanged.
- **Trusted resource policy in the actual browser board.** An optional paired policy now reaches published/restored browser copies, with source-resource capabilities/provider instructions reflecting the explicit selection while default Pages remains closed. Real board/canvas/bridge acceptance uses URL-based MCP and the host writer for declared image/font edits, atomic History navigation, changed MIME/size descriptions, canonical IndexedDB/source download/copy/reopen and clean page painting. Pixels, font advances and same-iframe/root/input drafts survive live changes; unsupported query/use/cycle, invalid/missing resources and oversized candidates retain accepted state/storage. Targeted restore-binding and stale-description controls fail their respective oracles. Literal/declared drivers share fixture/probe code without replacing product modules. Guarded node Copy/Cut, separate browsing/complete retirement and installed/default activation remain gated; the source-versus-device capability boundary is corrected separately above. No dependency, schema or CSP change.
- **Pair browser writer byte admission with preview preparation.** An optional trusted BrowserRuntime resource policy now captures byte access and projection together across read/patch/history/source/persist, leaving default browser gates and board composition unchanged. Payload-free descriptions retain aliases/unused names and install with accepted settings. Final validation/serialization now precedes accepted render-ID allocation; late refusal retains model/render/history/storage/events while underlying storage failures keep the existing diagnostic-and-accept policy. Shared Node/Chromium witnesses cover byte/frame edits, nullable grouped replay, canonical callback persistence/reopen and page/fragment closure, with independent missing-binding/allocation controls. This is private writer evidence, not actual-board declared-resource paint, IndexedDB/download/clipboard integration or default activation; no dependency, schema or CSP change.
- **Carry trusted project byte access through shared semantics.** Project settings/read/patch/write and project-history replay/round-trip proof now accept one optional host-owned byte-access function, reusing the same asset validator and preserving the bundle-selected port when omitted. The callback can refuse but cannot replace source or validation; nullable restoration carries it into final revalidation. Authored Node/Chromium witnesses prove retention, refusal phase/identity and unchanged browser-default authority after explicit calls; a missing history binding fails independently. That semantic-only step left runtime/board selection and default byte/profile activation closed.
- **Share asynchronous browser standalone export.** BrowserRuntime now sends full-page and selected-fragment exports through the existing portable single-file projector, matching native closure/refusal semantics; the board page adapter awaits it before cloning. Node-ported closure/fragment/version/refusal tests retain accepted state, while actual browser acceptance renders clean exported literal-resource HTML from the real page port. A missing await is captured as a Promise-cloning failure. Default browser byte admission and resource-aware node export remain closed; no dependency, CSP or schema change was introduced.
- **Witness queued old-port rejection after reset.** Browser acceptance now delays a genuine port-delivered text-edit event's original callback until its frame/port retire, then drains both UI and runtime writer queues and requires unchanged accepted content/history/IndexedDB. The new genuine port must still persist/render an edit and Undo it. An isolated receiver-guard removal accepts stale content and breaks the oracle. This is test/documentation coverage of the existing guard, not a transport/authentication change or proof that closed endpoints deliver new traffic.
- **Witness preview timeout and unmount retirement.** Actual-board acceptance now holds the existing bridge script to distinguish the native four-second fallback from authenticated paint. Initial release of divlet: a local HTML/SVG/CSS layout board for agents. The native project format remains an unfrozen schema-1 draft; this release does not activate the approved future ordered-CSS/renderer profile or promise frozen compatibility.

### Product and agent integration

- **One product, three real adapters.** `@divlet/core` supplies the model/runtime/server, bundled plugins and portable workflow skill. The separate `@divlet/web` owns the only browser client and portable host ports, without a core/Node dependency; the HTTP composition uses its public asset locator. `@divlet/cli`, `@divlet/mcp` and `@divlet/pi` own their commands and implementations, with exact matching core dependencies; core pins web. All five release versions match. CLI/MCP/Pi own their real packages directly in `cli/`, `mcp/` and `pi/`, beside core and web; workspace, build, source/installed entrypoints and documentation follow the flat topology without wrappers. The unscoped `divlet` npm name was refused by registry policy; the product, command and tool identities stay divlet. Node.js 22.19 or later is required; CLI and MCP do not require Pi.
- **Seven shared validated tools.** Pi and MCP use the same open/read/patch/structural-edit/frame/history/work-mark contract, revisions and refusal codes. Board requests carry the submitted selection snapshot and compact context rather than following later selection changes. MCP sampling and Pi model/thinking controls appear only when the host advertises them; session settings are not project content.
- **One live writer per project.** Other clients attach to the owning board and share its revisions and history. Importing the library or an adapter starts no service. Installed packages use compiled exports; checkout development runs TypeScript sources without a build.

### Native projects and files

- **Real web content in independently owned files.** A `.divlet` contains frames, shared tokens/CSS, reusable components, property overrides and inert metadata. Valid external edits are accepted; invalid or stale candidates preserve the last working state. Discovery and the launcher distinguish exact project files, including same-named projects.
- **Bounded HTML admission and foreign-format conversion.** Static HTML imports use the core sanitizer; PEN interpretation belongs to its importer plugin. Conversion creates a non-overwriting sibling project and preserves the original. Markdown sites retain routed pages and shared templates.
- **Embedded resources with explicit identity.** Image uploads and declared files retain their bytes in a hierarchical Data-URL asset tree, materialized only as rebuildable output. Explicit `asset:` references preserve names, MIME and dependency bases; literal Data URLs stay inline. Existing filesystem inputs remain supported without silent absorption.
- **Owned static output and export.** Generated HTML/resources have per-project provenance, collision/link refusal and repairable sidecars. Supported local dependencies survive portable publication below a URL prefix. Clean per-frame HTML export embeds supported resources; ambiguous query, SVG-use, cycle or expanded-size semantics refuse rather than silently change meaning. Save a copy creates an independently identified project.
- **Device fonts use ordinary CSS and common assets.** Family selection preserves understood fallback stacks and inline priority. TTF/OTF, bounded WOFF 1 and restricted null-transform WOFF2 registration retain exact submitted bytes and append only proven disjoint companions. Upload and selection are separate Undo steps. Static CFF2 and independently encoded CFF1 WOFF fixtures exercise actual browser matching and portable loading.

### Board and editing

- **Long-lived live artboards.** Lazy iframes retain identity through edits, zoom and selection. Expanded browsing is separate from authenticated editing; known page/fragment links reveal their artboards, and projected missing-page links report the unsupported destination. Browser-generated snapshots embed proven font bytes; stale or unprovable captures keep the live page instead of showing fallback-font text.
- **Direct, responsive inspection.** Layers, bottom breadcrumbs, one vertical inspector flow and adaptive toolbars expose layout, typography, appearance and metadata. Spacing uses outside-in box bands with independent side values and measured content dimensions. Border has two synchronized views and one writer. Controls retain whole values, keyboard access and useful narrow/200% layouts.
- **Guarded whole-project history.** Grouped and multi-step Undo/Redo validate the complete candidate, refuse overlapping later edits and persist before moving stack authority. Frame lifecycle/order replay preserves authored positions. History state points name proven stack endpoints, not audit sequence numbers.
- **Stable conversation and feedback.** The agent pane follows arrivals near the bottom without stealing older reading positions. Activity/Stop moves as one surface when the sidebar folds. Delayed agent-start notices defer for a bounded interval to preserve the ordinary Undo window, and deleted artboards no longer publish queued measurements.

### Safety and boundaries

- **Local, bounded access.** The board binds to loopback with token-scoped routes, Host/Origin checks, CSP and request bounds. Filesystem operations use regular-file/no-link checks, byte/count budgets and non-overwriting publication. Trusted project access is not an arbitrary HTTP filesystem route.
- **Authenticated previews.** Editing traffic uses a current document-bound MessagePort with capability rotation, sandboxing and referrer protection. A matching iframe window alone is not authentication. Stale observations, captures and async reads cannot replace newer accepted state.
- **Explicit current limits.** Arbitrary application scripts, managed-HTML reverse editing, an offline browser writer and automatic public-safe snapshot curation are not implemented. Transformed WOFF2, font collections/optional container blocks, ambiguous face merging, wider linked/imported/dynamic font capture and native external SVG-use remain refused or gated. Variable CFF2 and arbitrary font-program compatibility are not established by static fixtures.
- **Separate evidence layers.** Source/unit/browser, local installed-tarball, registry-install, static-host and format-freeze evidence are distinct. Strict Node/core types and a small checked client transport slice do not imply whole-client typing. The portable browser semantic slice is not a complete offline editor.

Pre-release implementation and retired-experiment history remains in Git. See [testing](docs/testing.md) for executable checks and their coverage limits; future work is tracked only in the backlog.

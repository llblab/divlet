# Changelog

This file records implemented project changes, not plans or contributor rules. Open work is tracked in [BACKLOG.md](BACKLOG.md).

## Unreleased — preparing 0.0.1

This is the first release in preparation. No version has been published.

### Added

- **Agents build meaningful navigation by default.** The divlet skill now requires real page/section destinations for navigation and button-styled links, even when navigation was implicit in the site request; no invented routes or empty/hash placeholders. It distinguishes stable frame IDs from display names and internal node IDs from DOM anchors, audits component-instance links, and calls for actual navigation checks rather than geometry-only confidence. Executable insert examples resolve to unique targets in a portable build under a deployment prefix. A separately reproduced preview-base 404 gap is recorded in the backlog; no runtime URL workaround or preview fix is claimed.
- **The approved format transition has a shared ordered CSS foundation.** `core/lib/declarations.ts` defines declaration/operation pairs, non-mutating first-position set/remove semantics, case-sensitive custom properties and order/fallback-preserving serialization. Indexed slots avoid rescanning the full block for each edit. Preview, generated-file and clean-export inline emitters use the serializer with unchanged legacy-map output; ordered contracts are exposed through the model's type surface. Focused tests cover purity, repeated declarations, large edit sequences and legacy merge equivalence. The profile is approved for implementation, but active project-2/frame-1 admission, CSS layering and draft files are unchanged; schema cutover, renderer requirements and explicit migration remain open. Asset packaging is a separate recorded decision gate.
- **The format policy proposal is explicit, not a premature freeze.** `docs/format.md` separates current schema-2/frame-1 admission from an unapproved project-3/frame-2 proposal: ordered inline declarations, native CSS emission, order-independent effective overrides, consumer component scope, literal unique DOM IDs and explicit renderer identity. Read-only Chromium probes exposed implicit components-layer priority even without an engine and style-map reordering that changes 10px/20px padding while current deep comparison reports equality. The proposal names alternatives, migration consequences, implementation owners and approval evidence; the backlog now gates implementation on the profile decision. No runtime, schema, migration command or compatibility guarantee changed.
- **Native context and stored-override budgets are enforced at shared admission boundaries.** One table grammar now constrains both container children and required parents, including roots and expanded instances; valid tables and reusable rows remain supported. Paragraph validation covers four additional browser-closing tags, and table text uses HTML whitespace so foster-parented NBSP/EM SPACE cannot silently disappear. Stored override metadata now reuses the ordinary validator before null deletion can hide its size; the diagnostic names serialized UTF-16 units accurately. Exact 65536/65537-unit checks retain safe application data, recursive merging and deletion semantics. The portable corpus now has four accepted inputs and 20 rejected cases, with static projections checked for every accepted frame and a supported-tag simple-tree fidelity gate. No schema fields/version or frozen compatibility status changed.
- **The freeze assessment separates local admission gaps from persisted-policy choices.** Two independent reviewer lenses and a reproducing verifier examined `6435d97`, with their findings checked against the original reports rather than treating synthesis as fresh verification. `docs/format.md` records concrete table-context and override-metadata-budget gaps, numeric equivalence and component counterexamples, and why WEB-1/WEB-2/WEB-5 are not blanket wire-format prerequisites. The backlog replaces assessment work with the two bounded admission fixes and retains explicit semantic/compatibility approval gates. No implementation changed or compatibility freeze was declared by this assessment.
- **Pre-freeze validation shares one name/metadata policy instead of preserving reader quirks.** Project names now reuse the model string validator, retaining project error codes while normalizing line endings and rejecting unrepresentable names. The metadata validator rejects non-JSON/non-finite values and unsafe keys at every owning entry point, preventing project metadata overflow from being saved as null while preserving arbitrary supported application JSON. Override attribute types now admit the null deletions already supported by the reader; literal element attributes remain strings. The reader audit is green and part of the baseline, with runtime coverage for retained accepted state/output and invalid authored bytes. This deliberately tightens unpublished input validation without adding schema fields or renumbering the schema; it is not a freeze declaration.
- **The format candidate has a portable baseline and a reader audit.** Three accepted JSON examples and 17 rejected cases exercise defaults, semantic project read/write, native web content and component addresses through `npm run test:format`; the specification's example/tag lists are checked too. The initial audit exposed four reader inconsistencies, which were subsequently aligned before freeze; the retained witnesses remain executable regression evidence, not a promise to preserve their old behavior.
- **A first-release format candidate replaces the brief wire-format sketch.** `docs/format.md` now documents complete project input, defaults, identity, components/overrides, the supported web profile, CSS/resources, revisions and compatibility boundaries. The backlog isolates conformance evidence, freeze assessment and final approval from editor implementation and npm publication. This is a specification/preparation change, not a frozen compatibility promise, schema renumbering or runtime change.

Explicit HTML/HTM opening, dropped pages and re-import use the same core admission profile without a style engine or HTML plugin registration. Scripts, handlers, comments, external stylesheet links and frames are dropped and counted; HTML is not offered as a project in folder listings. The moved core regression suite and the web-native stabilization gate cover these boundaries. ### Changed

- Tests: the Appearance radius check waits for the panel's redraw instead of reading the field once (it failed about one run in three once the fold tabs changed the panel's redraw timing).
- Canvas: a cancelled drag drops its preview at once instead of keeping the artboard at the dragged position until the undo arrives — Escape restores immediately, and a gesture that starts in that window can no longer snapshot a stale preview as its starting rectangle.
- Canvas: an inline editor (rename, size) closes when the pointer goes down outside it. While it stayed open, a press on the artboard's own label typed into the field instead of dragging the artboard, and nothing on the board closed it.
- The Pi adapter is now a translation layer: its tool definitions come from the shared contract, and its own code is the `/divlet` command, the agent bridge, the skill and the launcher behaviour. The CLI is unchanged and keeps using the core directly.
- Canvas editing: **dragging an element by its grip reorders it live** — the tree moves while the pointer moves, in the drag's own undo group, so the layers panel, component instances and built pages follow the drop. This needed a move that names the sibling it goes beside (`{ type: 'move', id, after | before: siblingId }`, which `core/lib/ops.js` already supported) instead of a parent-and-index pair: repeating the same drop during a drag is then a no-op on a tree that has already moved, where index-relative moves made a second drop act on shifted children. The release message reuses the drag's group, so the whole gesture is still one undo step even when it arrives after the pointer is up. `spacing.mjs` asserts the order changes before the release and that one undo restores it.
- Inspector: the empty fields now quote the measurement of the render they belong to. A render that kept deferring while the pointer rested over the panel left them quoting the previous one (a pill's radius, `33554400`, after its class had already been removed); a deferred measurement now forces one flush once nothing is being typed or held and no menu is open. Reports from an older render are dropped instead of overwriting a newer measurement.
- Inspector: **typing an artboard's X, Y, W or H commits without Enter** too — same pause, same one-undo-per-focus, and the artboard, its label and its page follow the field while it is typed (expressions such as `1280/2` are still accepted, and text that does not parse waits for Enter or blur).
- Inspector: **typing into a number field commits without Enter**. After a short pause (140 ms) a value the parser accepts is sent, so the artboard, component instances and built pages follow the field while it is being typed; text the parser rejects still waits for Enter or blur, where it is reported as before. All commits of one focus session share a group, so the typing and the final Enter are a single undo step, and a commit that lands mid-typing does not redraw the panel (it would replace the input under the caret — the deferred render arrives on blur).
- Canvas editing: cancel is scoped and the drag's preview is too. A gesture cut short (Escape or a window that loses focus) now waits for its own queued commits and undoes only when one actually landed, so it can no longer revert the previous, unrelated undo step and then let the drag's commit arrive as a new one. The preview rect stays authoritative for the whole gesture (a landed commit no longer makes the artboard step backwards mid-drag) and is dropped on release, on cancel and on a failed commit, so it cannot outlive the gesture. A patch that changes nothing is now refused by the runtime itself: no version bump, no History row, no undo step — which is also why the page's drag release can always state its final value (it may be the one a failed live commit missed) without poisoning History.
- Canvas editing: **moving an artboard is live and measured from where the drag started**. Every rect now comes from the pointer-down snapshot (as the resize path already did), so a landed commit cannot re-base the next delta — a slow 160 px drag used to move the artboard over 1600 px. Releasing no longer adds the delta a second time, a release that would commit the value the drag already committed sends nothing (no "no change" row in History), and the drag's preview rect is no longer latched past a lost gesture: a window that loses focus mid-drag cancels it (the page's drag is cancelled, the previews are dropped and what the gesture committed is undone) instead of leaving a rect that a later gesture would write back over someone else's change. Covered by `controls.mjs` (a slow drag moves by the pointer delta; a blur-cut drag leaves no stale rect) and `spacing.mjs` (no no-change row).
- Canvas editing: **moving and resizing an artboard is live too**. The frame already followed the pointer; the project now follows it as well (at most every 90 ms, in the drag's own group), so the inspector, the artboard's size label, components and the built pages read the value the pointer is at. The drag's preview rectangle stays authoritative until the release, so a landing commit never makes the artboard jump back, and `Escape` during a drag that already committed undoes it and puts everything back. Covered by `controls.mjs` (the project moves before the release; one undo reverts the whole drag) and `interact.mjs` (the page reflows and the model agrees).
- Canvas editing: a pill drag (margin, padding, gap, size) is **live**. The element already followed the pointer through inline styles; now the drag also commits while it runs (at most every 90 ms), so the project, the inspector's numbers, component instances and the generated pages follow the pointer instead of waiting for the release. Everything the drag commits shares one group, so it is still a single undo step whose label names the value it settled on, and the frame being dragged holds its own preview so no re-render rips the page out from under the pointer (`web/lib/store.js` gained `idle(documentId)` for that hand-off).

## Unreleased

- **Physical provider-absence prototype.** A temporary production-source copy with only the closed parser dependency graph now exercises shared frame admission, direct inline CSS edits, refusal integrity and HTML/project round trips through the existing provider-free style port. Checkout escape and missing-parser controls refuse; selected dependency roots are preserved without links, installs or polyfills. Minimum Node 22.19 and Node 26 pass. The test-only port selection is not production bootstrap, and public defaults/legacy `styles` behavior are unchanged.
- **Standalone composition compatibility guards.** Fresh-process public model/engine import and synchronous require, plus importer ESM import, now refuse accidental library-root initialization in regression tests. Late standalone/root imports must retain explicit empty/custom engine selection, exact renderer identity, importer first-claim order and ID deduplication. The async importer graph is documented separately from the synchronous model/engine entries; runtime defaults, provider selection and package exports are unchanged.
- **CSS-native PEN conversion.** New imports retain declaration order/priority in ordinary project CSS, use collision-avoiding data-attribute selectors and require no declaration-to-class engine. Authored classes/inline CSS, shared stylesheet order, explicit variables and matching component instances remain intact; equal-valued literal colours are no longer implicitly coupled to variables. Ambiguous aliases/projection references and native capacity overflows refuse without publishing a partial project. Three-frame Chromium fidelity passes with the default provider and with no registered engine; existing native/imported files and foreign source bytes are not rewritten. Physical optional-package/bootstrap independence remains open.
- **Renderer identity discrepancy diagnosed.** Controlled offline installations showed different tokens came from selected compiler/transitive versions, not source/build paths: equivalent selected inputs in a relocated installation retain the same token and exercised CSS. Added an opt-in actual-recipe/manifests audit, exact-match checks and release-smoke input diagnostics so future token differences remain attributable. Renderer policy, matching, dependency ranges, defaults and stored requirements are unchanged.
- **Byte-preserving project opening.** Existing native sources are no longer canonically rewritten just to generate or rebuild their owned cache. Formatting, omitted defaults and duplicate-key evidence remain intact for explicit conversion; accepted draft semantics and schema 1 stay unchanged. Both source-conflict checks and canonical candidate validation remain active, raw disk hashes prevent echo edits, and explicit changes/Undo/Redo still save normally. Regressions cover default/custom output, cache deletion/reopen, source races and both writers.
- **Native JSON text-profile foundation.** Added opt-in `parseNativeJson` with caller-owned UTF-8/container budgets, escape-equivalent duplicate-name refusal, finite binary64 decoding and positive-zero normalization. It preserves opaque UTF-16 strings and array order, sanitizes diagnostics, and uses an iterative value walk rather than a recursive reviver. Shared Node/real-browser witnesses and typed `unknown` results keep lexical decoding distinct from schema admission; existing readers and wire fields remain unchanged.
- **Structural rendering requirements foundation.** Added opt-in `validateRequirements` through the project entry, decoding explicit native CSS or an exact renderer identity without provider lookup/loading. Native requirement types share one vocabulary, the engine type export remains compatible, and identifier grammar is reused without activating new wire fields. Node-only-file closure and real browser vectors cover unknown identities, strict records, opaque version bounds and input isolation; project reads and settings patches still refuse `requires` until coherent cutover.
- **Ordered CSS admission foundation.** Added opt-in `validDeclarations` for ordered literal declarations and nullable override operations, retaining duplicates, order and source isolation. It shares the existing CSS safety/normalization guard with map-style validation and has typed Node/browser witnesses. Stored style fields remain maps: this does not switch the draft wire format, implement native style operations or migrate sources.
- **Aligned left-column sizing.** The sidebar's default and minimum now follow the measured DIVLET/search row, including button borders and the gap, in logical interface pixels. The desktop maximum stays 560px. Live header changes update the bound without overwriting a saved preference; reset returns to the measured default, and phone sheets keep their existing full-width layout.
- **Connection-aware Agent setup.** Disconnected boards show connection instructions and the exact command in a read-only selectable field with a corner Copy button, rather than an invitation to an unavailable conversation. The card follows the host's reported agent state, preserves earlier messages and replaces the hidden-command footer action. Conversational hosts retain the connected empty-chat invitation; tool-only browser MCP keeps the conversation in the agent and hides the unsupported composer. Clipboard refusal selects the visible command for manual copying.
- **Collapse from expanded viewing.** The return control now places four inward-pointing arrows to the right of its label instead of a leading back arrow. The standalone landing keeps “Edit on the board”; the accessible label and tooltip describe collapsing, not browser-history navigation. Dragging, Escape and keyboard activation retain their existing behaviour.
- **Style ownership clarified (documentation only).** The target contract assigns native CSS and ordinary inspector controls to the core in Node and browser hosts; Tailwind adds a linked atomic-class editor/compiler, including the standalone landing composition. Existing WEB/BROWSER tasks now separate native operations, inspector migration, provider admission, linked representation and demo integration with explicit checks. No runtime implementation, format migration or browser Tailwind delivery is claimed.

## 0.0.3 — 2026-11-13

- **The board runs as a static site that is its own MCP provider.** `scripts/pages-build.mjs` builds the GitHub Pages set: the real board client with a bundled browser host that opens the canonical landing project in the visitor's browser, keeps the visitor's copy in IndexedDB until the publication changes, and exposes `read_divlet`, `patch_divlet`, `edit_divlet`, `frame_divlet`, `undo_divlet` and `mark_divlet` through the page's MCP provider (and WebMCP when a browser offers it). A first visit reads the landing expanded at the window's width, with live updates, one step from the board. Native-only affordances (opening files, save-as, build output, image/font upload, the board conversation) are absent there; Copy/Download HTML and "Download project file" run in the page. The Pages workflow tests the built set in Chromium and publishes it only when its fingerprint changes. Deployed to GitHub Pages; all five packages published and verified through the CI/OIDC release.
- **`divlet-mcp --connect <url>`** connects any MCP host to such a website: the site opens in a managed, isolated Chromium and its tools run in the page. Both MCP eras are answered on stdio; website descriptions are marked as website text, annotations are dropped, results are reduced to text and JSON, cross-origin redirects are refused and a reloaded page is reconnected explicitly.
- **Reusable browser MCP layers.** `@divlet/web/mcp` (one tool registry with bounded JSON Schema validation, an MCP 2026-07-28 browser provider with a versioned page endpoint, optional WebMCP registration) and `@divlet/core/browser-mcp` (the agent-side transport, also as an SDK-shaped `Transport`). The official MCP TypeScript SDK client interoperates with both.
- **A browser-local project writer.** `BrowserRuntime` runs the shared contract tools over the shared kernel; shared vectors require identical models, pages, refusals, history and serialized projects to the Node runtime. `project`, `codec`, `diff`, `ops`, frame preparation, acceptance rules and the tool list no longer reach Node built-ins; embedded asset decoding refuses explicitly in browser builds.
- Breadcrumbs keep the selected artboard visible as the current crumb, followed by › and a `root` step into its root element, instead of folding the path to a lone icon.
- The board reaches its host through writer, preview, export and component ports; a complete alternative composition can replace the native HTTP routes without fallback.

## 0.0.1 — 2026-11-13

Published `@divlet/web`, `@divlet/core`, `@divlet/cli`, `@divlet/mcp` and `@divlet/pi` on npm with matching versions and verified archive integrity. Clean registry installations exercise the standalone board, CLI/MCP tools and an isolated real Pi host.

Initial release of divlet: a local HTML/SVG/CSS layout board for agents. The native project format remains an unfrozen schema-1 draft; this release does not activate the approved future ordered-CSS/renderer profile or promise frozen compatibility.

### Product and agent integration

- **One product, three real adapters.** `@divlet/core` supplies the model/runtime/server, bundled plugins and portable workflow skill. The separate `@divlet/web` owns the only browser client and portable host ports, without a core/Node dependency; the HTTP composition uses its public asset locator. `@divlet/cli`, `@divlet/mcp` and `@divlet/pi` own their commands and implementations, with exact matching core dependencies; core pins web. All five release versions match. CLI/MCP/Pi own their real packages directly in `cli/`, `mcp/` and `pi/`, beside core and web; workspace, build, source/installed entrypoints and documentation follow the flat topology without wrappers. The unscoped `divlet` npm name was refused by registry policy; the product, command and tool identities stay divlet. Node.js 22.19 or later is required; CLI and MCP do not require Pi.
- **Seven shared validated tools.** Pi and MCP use the same open/read/patch/structural-edit/frame/history/work-mark contract, revisions and refusal codes. Board requests carry the submitted selection snapshot and compact context rather than following later selection changes. MCP sampling and Pi model/thinking controls appear only when the host advertises them; session settings are not project content.
- **One live writer per project.** Other clients attach to the owning board and share its revisions and history. Importing the library or an adapter starts no service. Installed packages use compiled exports; checkout development runs TypeScript sources without a build.

### Native projects and files

- **Real web content in independently owned files.** A `.divlet` contains frames, shared tokens/CSS, reusable components, property overrides and inert metadata. Valid external edits are accepted; invalid or stale candidates preserve the last working state. Discovery and the launcher distinguish exact project files, including same-named projects.
- **Bounded HTML admission and foreign-format conversion.** Static HTML imports use the core sanitizer; PEN interpretation belongs to its importer plugin. Conversion creates a non-overwriting sibling project and preserves the original. Markdown sites retain routed pages and shared templates.
- **Embedded resources with explicit identity.** Image uploads and declared files retain their bytes in a hierarchical Data-URL asset tree, materialized only as rebuildable output. Explicit `asset:` references preserve names, MIME and dependency bases; literal Data URLs stay inline. Existing filesystem inputs remain supported without silent absorption.
- **Owned static output and export.** Generated HTML/resources have per-project provenance, collision/link refusal and repairable sidecars. Supported local dependencies survive portable publication below a URL prefix. Clean per-frame HTML export embeds supported resources; ambiguous query, SVG-use, cycle or expanded-size semantics refuse rather than silently change meaning. Save a copy creates an independently identified project.
- **Device fonts use ordinary CSS and common assets.** Family selection preserves understood fallback stacks and inline priority. TTF/OTF, bounded WOFF 1 and restricted null-transform WOFF2 registration retain exact submitted bytes and append only proven disjoint companions. Upload and selection are separate Undo steps. Static CFF2 and independently encoded CFF1 WOFF fixtures exercise actual browser matching and portable loading.

### Board and editing

- **Long-lived live artboards.** Lazy iframes retain identity through edits, zoom and selection. Expanded browsing is separate from authenticated editing; known page/fragment links reveal their artboards, and projected missing-page links report the unsupported destination. Browser-generated snapshots embed proven font bytes; stale or unprovable captures keep the live page instead of showing fallback-font text.
- **Direct, responsive inspection.** Layers, bottom breadcrumbs, one vertical inspector flow and adaptive toolbars expose layout, typography, appearance and metadata. Spacing uses outside-in box bands with independent side values and measured content dimensions. Border has two synchronized views and one writer. Controls retain whole values, keyboard access and useful narrow/200% layouts.
- **Guarded whole-project history.** Grouped and multi-step Undo/Redo validate the complete candidate, refuse overlapping later edits and persist before moving stack authority. Frame lifecycle/order replay preserves authored positions. History state points name proven stack endpoints, not audit sequence numbers.
- **Stable conversation and feedback.** The agent pane follows arrivals near the bottom without stealing older reading positions. Activity/Stop moves as one surface when the sidebar folds. Delayed agent-start notices defer for a bounded interval to preserve the ordinary Undo window, and deleted artboards no longer publish queued measurements.

### Safety and boundaries

- **Local, bounded access.** The board binds to loopback with token-scoped routes, Host/Origin checks, CSP and request bounds. Filesystem operations use regular-file/no-link checks, byte/count budgets and non-overwriting publication. Trusted project access is not an arbitrary HTTP filesystem route.
- **Authenticated previews.** Editing traffic uses a current document-bound MessagePort with capability rotation, sandboxing and referrer protection. A matching iframe window alone is not authentication. Stale observations, captures and async reads cannot replace newer accepted state.
- **Explicit current limits.** Arbitrary application scripts, managed-HTML reverse editing, an offline browser writer and automatic public-safe snapshot curation are not implemented. Transformed WOFF2, font collections/optional container blocks, ambiguous face merging, wider linked/imported/dynamic font capture and native external SVG-use remain refused or gated. Variable CFF2 and arbitrary font-program compatibility are not established by static fixtures.
- **Separate evidence layers.** Source/unit/browser, local installed-tarball, registry-install, static-host and format-freeze evidence are distinct. Strict Node/core types and a small checked client transport slice do not imply whole-client typing. The portable browser semantic slice is not a complete offline editor.

Pre-release implementation and retired-experiment history remains in Git. See [testing](docs/testing.md) for executable checks and their coverage limits; future work is tracked only in the backlog.

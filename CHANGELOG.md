## Unreleased — preparing 0.0.1

This is the first release in preparation; no npm version has been published. The entries below consolidate successive pre-release implementations into their retained outcomes. Detailed earlier notes remain available in the source checkout with `git show 3d54b51:CHANGELOG.md`; retired experiments are distinguished from current APIs below.

### Native projects, import and output

- **One HTML/SVG/CSS-oriented project model.** Independently identified `.divlet` files contain frames, reusable components/overrides, shared tokens, CSS and inert application metadata. Native project and standalone-frame envelopes use initial schema 1; no format has been frozen or officially released. The initial-marker correction is separate from npm 0.0.1 and content revisions, preserves inert metadata, and refuses unsupported markers without implicit migration. Default creation is `project.divlet`; discovery, the launcher, picker, browser titles and tool results distinguish exact files, including same-named projects. Invalid external edits retain the last accepted state. Managed-HTML hand edits are diagnosed and preserved, not imported as an editing round trip.
- **Shared admission and validation.** Project names reuse the model's representable-string rules. Metadata rejects non-JSON/non-finite data and unsafe keys, including stored overrides before merging/deletion; supported application data remains extensible. Literal attributes stay strings, while override null deletion is typed. Shared table/parent and paragraph-context checks include expanded components and HTML whitespace semantics. SVG tag/attribute case, filter definitions and referenced DOM IDs survive supported import/codec paths. Typed optional `head.description`/`head.icon` retain escaping, safe URLs, resource closure, strict physical-head/manifest agreement and merge/null/history semantics; they do not admit arbitrary scripts or head markup. See the [format reference](docs/format.md).
- **Native HTML admission, foreign importer plugins.** Explicit HTML/HTM opening, dropped pages and re-import share the core sanitizer and bounded, non-overwriting conversion driver without an HTML plugin or style engine. Dropped scripts, handlers, comments, linked stylesheets and frames are counted in provenance. Foreign files convert once into a sibling `.divlet`; originals and existing destinations are not overwritten. Legacy `.divlet` files containing a foreign source move their original bytes to a free `.pen` path before conversion. HTML files are explicit inputs, not projects in folder listings. Changed imported sources offer **Import again** into a fresh sibling rather than merging over edited work.
- **PEN conversion retains reusable structure.** The importer owns PEN reading/validation, projection and shape rendering, lowering supported content into ordinary HTML/SVG/CSS and optional Tailwind classes. Variables remain live through CSS tokens; nested component instances and overrides remain instances where representable instead of being flattened. Unsupported sources retain diagnostics rather than gaining invented content or native editing authority. Historical conversion measurements and their corpus limits are recorded below.
- **Owned, portable generated output.** Generated HTML, metadata and resources live under `.divlet/<source-name>/` or the explicit relative `outputDir`. Relative provenance manifests, exclusive locks and whole-plan preflight protect unowned/colliding/linked paths; owned hand edits are preserved in recovery trash. Output moves retain routed-page ownership, even after the final frame is removed. Portable builds close supported local HTML/CSS/SVG/image/font dependencies, rewrite editor URLs, effective bases and escaped CSS/resource references, retain query/fragment semantics and work below a deployment prefix. Per-frame **Copy HTML** and **Download HTML** remain available; the retired site-ZIP control is not a current export API.
- **Resource-context data URLs.** Images/media `src`, posters and typed favicon URLs admit inline data without granting ordinary links or form destinations data-document navigation. CSS and srcset retain their existing data support. Both percent-encoded and base64 image URLs survive admission, strict codecs, native storage, output rebuild after cache removal and ordinary icon Undo; string/document bounds and executable-scheme refusal remain. Real-preview checks load SVG data under the existing CSP and observe both message receivers with a positive control. This supports self-contained small examples, not the unfinished shared binary-resource table.
- **Source-aware copies and resource refresh.** Save As creates an independent validated source/resource copy without overwriting an existing destination; escaping or aliasing output destinations are reset for the copy. Local dependencies resolve automatically, including permitted external paths, without manual exact-file grants or a general HTTP filesystem route. Resource-only edits and missing-resource recovery refresh derived output without inventing frame edits. Authored images use private staging, exclusive allocation and byte/identity verification rather than racing filename probes; ordinary clipboard/drop/upload and image replacement preserve source-relative resources.
- **Markdown sites.** A shared template composes routed Markdown pages with relative links/resources. Direct/transitive component and shared CSS/token changes invalidate affected routes even when the template source version stays unchanged. Content updates, deletion and invalid-content recovery reconcile owned output while preserving the accepted project. Site composition remains distinct from ordinary frame preview and standalone HTML export.
- **One native landing source, one directory per example.** `examples/landing/landing.divlet` supplies the editable English `index` demo and narrowly tracked `examples/landing/.divlet/landing/` Pages cache. Its small SVG favicon is embedded as a data URL; no external landing assets input or separate authored marketing tree remains. Handbook and studio own sibling directories; removed authored PEN demos do not remove importer support. Build/check uses the normal owner or a relocated sandbox. Node-22 Pages CI checks types, source/cache freshness and landing/resource regressions; the fingerprint/copy owner publishes only validated public HTML/resources plus `.nojekyll`, excluding sidecars, manifests, locks, trash and private data. Identical public bytes need no deployment commit. The authorized prerelease push passed Landing CI; live Pages HTML and its public fingerprint match the prepared bytes. Default-workspace template copying remains separate work; npm is still unpublished. See [examples](examples/README.md).

### Canvas, inspector and conversation

- **Long-lived real previews.** Each artboard keeps one browser-lazy iframe, promoted to eager loading for selected/expanded frames. Pan/zoom/deselection no longer drive unmount/prefetch cycles. Far-zoom WebP pictures are captured client-side through the private bridge, one at a time, and hand back to the same loaded page without a server screenshot service. Expanded return uses a fresh authenticated frame behind a ghost of the previous page rather than flashing a blank replacement.
- **Links work in Play.** A `#fragment` or bare `#` link in a previewed page scrolls its target in place, and a link to another artboard's page reveals and selects that artboard and scrolls it to the fragment, instead of following the project-files `<base>` to a missing path. Frames stay loaded, authored hrefs are unchanged and Select still inspects. Links to unknown pages do nothing; site routes and queries are not followed.
- **Expanded viewing opens content immediately.** The site template opens its routed content, while an ordinary frame opens its exact prepared public page, supporting native fragments, cross-frame links and linked local CSS/images. Entering this read-only document retires the editor port and rotates its capability; the page receives only a nonce-authorized Escape helper, not model/edit authority. Public files are captured before editor sidecars join the disk repair plan. Closing reacquires authenticated editing. This does not claim to fix the separate scaled-canvas Play/resource-base navigation gap.
- **Live, grouped manipulation.** Artboard movement/resizing, margin/padding/gap/size handles, sibling/container reordering, nudges and inspector scrubs commit while interacting and retain gesture groups through delayed delivery. Deltas derive from pointer-down snapshots rather than compounding accepted moves. Escape/blur/lost gestures cancel only their own settled work and leave no stale preview rectangle; no-op release adds no edit. Alt-copy, axis/pair/all-side modifiers, pixel stepping, alignment/distribution/tidy and keyboard operations retain their existing paths. Selection is ephemeral: deleted targets drop out rather than turning ordinary UI races into malformed-selection errors.
- **One vertical inspector and a measured box model.** Native disclosures replace section tabs, ordering preferences and jump overlays. Position → margin → border → padding bands surround measured content dimensions, with eight independent margin/padding fields, outer positioned offsets, measured per-side borders and single-side highlighting. Signed/fractional values remain readable; long values expand instead of clipping and missing/mixed/no-box measurements show `—`. Measured geometry/overflow stays last, after Metadata. Appearance keeps radius/border pairing, fill/text colours, palettes and multi-selection editing; declarative styles replace supported existing utilities, including project-colour classes. Arbitrary border/radius readback limitations remain in the backlog.
- **Stable drafts, focus and measurements.** Numeric fields accept arithmetic and commit after a pause with one group per focus; invalid drafts wait for explicit completion. Z-index uses signed unitless integer steps and preserves `auto` until intentional editing. Inline name/size editors finish once, retain focused drafts and cancel without blur-saving. Geometry-only observations do not replace active typing, colour choices, menus or pressed controls; stale render measurements are discarded. Caption/control pairs, units, intrinsic field grids, multiline selector centring and full wrapped class/tooltip text keep narrow controls usable.
- **Coherent, remembered chrome.** Separate DIVLET/search islands, bottom tabs, toolbar/inspector and bottom-centre breadcrumbs keep their roles; active tabs fold the sidebar without a duplicate corner close. Actions use the shared overflow list rather than separate menu implementations. Sidebar and inspector widths retain independent logical preferences, with cancellation/reset, blocked-storage recovery and same-origin propagation; constraints do not overwrite intent. This is origin/port-scoped browser storage, not cross-launch preference transfer. Layers always chooses an existing artboard while open and keeps its chooser independently scrollable above the element tree. Settings/output pickers keep stable controls and single folder labels.
- **Conversation and activity have one home.** Agent chat is a chronological bottom stack with blue/navy requests and neutral replies, follows new content near the end and preserves explicit older reading/focus. The composer shows submitted selection context and useful unsent starting prompts; Send/Queue stays bottom-right. One 5×3 activity plaque keeps elapsed time and Stop reachable, moves above fixed tabs while the whole left pane is folded and disappears there when idle/expanded. In the floating form, the spinner sits bottom-left, aligned with the timer and Stop, while the description uses the full width above; the open-panel layout is unchanged. Messages and errors do not move the controls they explain; connection help names the actual project and replies retain Copy.
- **Accessible controls and identity.** Light/dark/forced-colour controls use shared radii, focus, disabled and contrast tokens; tabs expose `aria-selected`, labelled controls retain whole text and touch targets are checked in tested contexts. The shared mark is an outlined open bracket plus a filled angular D with non-overlapping paint. Current narrow-tab and chat-focus limitations remain explicit rather than being hidden by old blanket layout claims.

### History and client command ownership

- **Atomic replay and authored order.** Undo/Redo composes complete groups or bounded multi-step traversals into one validated candidate/persistence, with stack authority moving only after acceptance. Frame membership restores original slots; external reorder/mixed membership transactions retain checked relative order and unrelated later frames. Selective frame replay remains available and overlap refuses without an accepted prefix. Pre-source failure preserves accepted state/stacks; post-source derived-output failure retains the existing diagnosed/retry policy rather than pretending the source rolled back.
- **Addressable session states.** Opaque point IDs follow proven stack endpoints, not audit sequence numbers or content snapshots. Group extension replaces partial frontiers; forward return retains IDs, new edits discard the old future, and selective/untracked changes expose explicit segment boundaries without deleting legacy stacks/activity. The real 200-group window is bounded independently of audit filtering. Browser reload retains owner IDs; runtime restart opens a fresh baseline. Resource bytes/site sources are not historical snapshots and revisions remain monotonic.
- **Guarded board navigation.** The owner advertises `history.navigation: true`; `POST api/history/navigate` captures `pointId`/`expectedPoint`, forces user attribution and rechecks the head inside the writer queue. Current-point navigation is a no-op, while stale/unavailable points refuse. Current/Ahead/Restore rows are distinct from the read-only Activity disclosure; older owners remain reveal-only, never a second writer. Keyboard/focus continuity, lazy/coalesced reads, point-only updates and read generations reject both A → B → A response races, including a replaced future at the same current ID. Cached payload/project/generation now form one read record rather than separately synchronized fields; rows capture their expected point from the explicitly supplied payload. Held failed/missing reads preserve refusal/reopen behavior without a new fetch pipeline.
- **Finite audit labels.** The two display dictionaries have no prototype: unknown actors, including `constructor`/`__proto__`, use the existing system label instead of crashing History; unknown kinds receive no function/object badge. Known labels, accepted records and history authority are unchanged. Real runtime/browser regressions cover known, ordinary unknown and inherited-name cases.
- **One lower artboard lifecycle owner.** The command facade and clipboard share creation/duplication/deletion functions without a dependency cycle or wrappers that change function identity. Deletion captures versions/names/component dependencies before optimistic hiding, then derives feedback from accepted targets. Component consumers precede definitions; partial failures restore only their own visibility and report actual successes. Already-hidden/missing targets do not create unguarded overlapping requests. Immediate toast Undo remains global Undo, not a command-pinned inverse when other edits intervene. Browser-module checks include plugin clients and literal lazy imports.

### Agents, packaging and implementation boundaries

- **First portable kernel admission slice.** The shared `DivletError`, refusal, plain-object/key, representable-text and JSON checks now live in a host-free module; the existing model re-exports the same bindings, preserving constructor identity and provider defaults. Shared Node/native-browser witnesses cover acceptance/refusal, UTF-16 limits, opaque JSON strings, finite numbers, unsafe keys, depth and error details without a second validator, Node polyfills or a backend API. Full frame validation, browser SDK delivery and offline/editor modes remain open.
- **One product, three real scoped adapter packages.** `divlet` owns the library, board, bundled plugins, common release notes and shared workflow skill. `packages/cli`, `packages/mcp` and `packages/pi` own their implementations/tests and publish as `@divlet/cli`, `@divlet/mcp` and `@divlet/pi`, each pinned to the shared product version. They replace `adapters/` and the separate `pi-divlet` wrapper; the root no longer owns bins, Pi metadata/peers or `divlet/pi`. CLI/MCP bins and explicit runners belong to their packages, with no service started on import. Workspace source conditions preserve native development without a build; publication uses separately owned compiled output, not copied adapter implementations in the product. Four local tarball installs verify CLI board startup, MCP version/protocol/seven tools, Pi registration/shared skill and Node-free plugin contracts; CLI/MCP need no Pi peers. Nested example paths, scoped landing commands and owned cache are reconciled. Consecutive-build snapshots guard against recursively compiling adapter output, and packed documentation checks retain the shipped link graph. The full browser battery is not wholly green: chat focus, narrow tab labels and a detached spacing element remain tracked rather than hidden by package success. The accidentally emitted `reuseImage()` signature remains deprecated and synchronously refuses with `UNSUPPORTED_OPERATION` without input/state/filesystem work.
- **Calibrated backend dependency boundary.** The bounded audit at `7b76afc` found 38 backend modules and 86 unique static local ESM edges after Node type stripping, with no runtime cycle. The source validator still reports 93 edges and the real model/engine source-type cycle; this is not full Domain DAG compliance. Three cold source-entry probes retain standalone model styles, Tailwind and PEN defaults. A root-only provider relocation was rejected as incompatible; composition/type-boundary work remains under WEB-2. The bounded drying pass stops at this inspected closure, not a claim that uninspected subsystems are dry.
- **One seven-tool contract.** Pi TypeBox and MCP JSON Schema/text envelopes share operations, result shaping, validation, revisions and domain errors. Attached clients reuse the existing token-scoped board owner; closing an attachment does not stop it. Project/collection views carry exact file targets, compact dependency summaries and bounded component-use lists; large frames expose outlines plus `view:nodes`/`full:true` rather than dumping every node by default.
- **One agent workflow and prompt grammar.** The portable product skill teaches install/open/read/edit/verify independently of host packaging. Board submissions carry selection snapshots and compact bracketed context; later selection changes do not retarget submitted tasks. Navigation authoring requires real page/fragment destinations rather than placeholders or runtime URLs. MCP sampling answers board prompts only when advertised; Pi's session-owned model/thinking controls appear when available, including on a fresh session, and report what the host actually applied. Session settings never become project content. The skill folder is self-contained (documents are named by their public address, not `node_modules`), and README/`docs/agents.md` document the two-step `npx skills add llblab/divlet --skill divlet --global` plus MCP registration path, with Pi's bundled skill not installed twice; a copied-skill test guards it.
- **Tests stay with their frontend owner.** `web/tests/` owns the Chromium acceptance scripts plus icon and client-module unit suites; server/model tests and shared core fixture builders remain in `core/tests/`. npm commands, Pages checks, filesystem/import bases and documentation follow the move without changing browser assertions. Production module scans and build asset copying exclude frontend tests; package and HTTP regressions keep them out of published and served assets.
- **Typed boundaries and publish-only builds.** Strict erasable TypeScript, real source specifiers and native Node execution cover migrated modules; builds emit JavaScript/declarations and package browser/plugin assets. Importer/exporter/style-engine/session contracts are exported and usable without Node-only types; JavaScript descriptors are admitted at registry boundaries. Browser JavaScript remains outside full `tsc` checking pending migration. The root README is an entrypoint into focused guides, source ownership has one current architecture map, and contributor/backlog/delivery responsibilities are separated. Release notes consolidate duplicated/superseded claims. Cross-package documentation uses repository links rather than relative paths absent from the product tarball; packed-link validation remains required when those links change.

### Safety and correctness

- **Validated acceptance, not optimistic persistence.** HTTP/tools enforce advertised frame/project versions and supplied render guards. Whole-project validation, frame-count symmetry, structural/component checks and output preflight precede accepted state. Invalid external bytes, stale operations and unsafe candidates preserve source/history/output authority rather than leaking a successful prefix.
- **Full-state freshness and recurring diagnostics.** Runtime-local `stateVersion` orders complete HTTP/SSE snapshots, including diagnostic/selection/agent changes at equal content revisions; clients refuse older or cross-identity state. Restoring known-good source clears invalid-hash suppression so identical invalid bytes recurring later regain diagnostics. This is distinct from History point/read-generation ordering.
- **Authenticated preview traffic.** Navigated iframes cannot reuse editor window messages or receive model/selection capabilities. Document-bound ports, capability rotation, sandboxing, nonce/CSP restrictions and no-referrer handling separate editing from opaque browsing; trusted editing resumes only after authentication. Matching `WindowProxy` identity alone is not authority.
- **Bounded local I/O and publication.** Regular-file/no-link descriptor reads, pathname/byte stability checks and aggregate allocation reservations protect source/resource work. Current resource work is bounded per file/aggregate/count; ordinary uploads have their own bound. Image staging/allocation avoids overwrite races and conservative cleanup does not claim arbitrary hostile-writer or native-Windows acceptance. Output provenance, exclusive locks and source-last preparation remain distinct from a crash transaction; local dependencies do not become arbitrary HTTP filesystem access.
- **CSS and resource fidelity.** Inline/token validation rejects sibling-rule injection, embedded CSS serialization protects closing-tag boundaries, and exact-candidate Tailwind compilation isolates theme/base/candidate sets instead of retaining unrelated URL utilities. Static planning preserves supported SVG paints, CSS escapes, effective bases and aliases while refusing private/generated inputs and output/input overlap. These outcomes do not establish every CSS context or a clean-export/reverse-editing contract beyond the admitted profile.

### Format transition foundations — not a cutover

- **Hierarchical asset admission foundation.** A standalone typed decoder validates canonical base64 Data URL trees, detached byte maps and authored relative paths under bounded file/source capacities. It preserves named duplicates and rejects unsafe or portable-alias paths, non-JSON/accessor/cyclic objects, malformed MIME/base64 and count/depth/path/byte overruns. Native field/reference activation, rendering, upload/copy/history and public output integration remain unfinished. The target now explicitly preserves use-site inline Data URLs instead of auto-extracting them.
- **Browser-host feasibility investigation.** Current HTTP/SSE and Node dependencies are documented alongside a proposed shared semantic kernel, explicit browser/Node hosts, static/offline demo modes and separate WebMCP/external-agent routes. Service Worker scope and browser capability probes are not presented as an externally reachable MCP server or implemented offline editor. The portable-kernel/demo/agent experiments and reusable landing-skill kit remain open work.
- **Candidate specification and executable admission evidence.** The format reference now owns defaults, identity, supported content, components/overrides, resource/revision rules and compatibility status. Reader audits and accepted/rejected/static-projection witnesses cover normalization, context and override-metadata budgets; exact 65,536/65,537 serialized UTF-16-unit cases are retained. Independent assessment separated local validation fixes from persisted-policy decisions instead of treating review synthesis as fresh verification.
- **Ordered CSS and exact renderer seams.** Pure ordered declaration/operation helpers retain order, fallbacks, property case and legacy-map equivalence; current emitters reuse their serializer without activating ordered wire data. Opt-in exact provider resolution refuses unavailable, mismatched, ambiguous or incapable renderers without installing, invoking or selecting a fallback. Tailwind's compiler-only descriptor binds provider stylesheet inputs to a portable policy/dependency/CSS fingerprint, with relocation, hostile ambient CSS and installed-factory witnesses. It is not code attestation; clean-install identity reproducibility and full resource/inspector binding remain open.
- **Approval is not implementation or publication.** The approved still-unfrozen schema-1 target design covers ordered CSS/native cascade, explicit requirements, consumer component scope/conflict/DOM-ID refusal, finite binary64/signed-zero equivalence and explicit non-overwriting migration-copy. These are not all active in the current draft reader, despite sharing the initial schema marker. Embedded-resource ownership is now selected, but storage/consumer implementation, conformance closure, final freeze and npm release remain separate unfinished steps; no implicit migration or frozen compatibility promise is introduced by these foundations.

### Evidence and superseded pre-release experiments

- **Retained executable gates.** Unit/source/codec/output/security, real Chromium, MCP stdio, Pi RPC, PEN fidelity and packed-install checks cover their declared boundaries. Release smoke installs local product/wrapper tarballs, checks CLI/board/plugin assets/MCP and plugin-author declarations, and publishes nothing. Browser tests use actual hit targets, editable focus, accepted models, current DOM subjects and temporal refusals rather than forced clicks or widened deadlines. Focused passes and independent reviews are not a claim that browser-all is uniformly green; current flaky/blocked cases remain in the backlog. See [testing](docs/testing.md) for commands and evidence scope.
- **Scoped historical measurements.** A non-bundled 68-frame design converted with 3,195 component instances, about 11.5k nodes and 5.5 MB versus earlier flattened 26.7k nodes/12.8 MB, retaining pixel parity on the measured corpus and roughly 30k live token references. Agent payload studies on that design reported project views of 35 KB versus 123 KB and component summaries of 63 KB versus 106 KB. A separate zoom witness sampled 196 animation frames with no blank handoff or iframe reload. The reproducible default fidelity command uses the shipped two-frame fixture; these external-corpus reports are not universal/current performance guarantees. An earlier external-HTML trial admitted 33/40 pages within the supported profile, not every page.
- **Retired native-PEN ownership/editing experiments.** Before the HTML-native model, pre-release work explored canonical PEN graphs, namespaces/versionless extension variants, property/tree/root/settings receipts, occurrence-local overrides/replacements, native HTML ownership/promotion, independent IDs, image/icon/path presets and source-aware Save As. It also exercised source-preserving ellipse/gradient/path/polygon/mesh policies; a fresh-process Unitema study reached 26 roots, without claiming Pencil-exact geometry, independent approval or that an already-loaded host had reloaded. The native runtime/writeback/promotion surface and its old frame/tool/namespace contracts were subsequently removed; retained PEN interpretation belongs to the importer. Historical HTML-looking ownership/link/viewport/bundle/ZIP experiments are not today's native-model APIs. Server screenshot/unmount scheduling and the duplicate corner-close/M/P-mode widgets were likewise replaced by the current surfaces above.
- **Retired upload/recovery and grant experiments.** Native `insertImage`, original-byte attestations, phase receipts, acknowledgement/retirement, recovery/reuse HTTP/browser protocols, fixed external-file grants and restart-approval flows were experimental stages, not retained current APIs. Their evidence distinguished asset publication from source acceptance, original admitted bytes from current-path observations, uncertain outcomes from safe retries, and source-only Undo from durable asset cleanup; receipts were not crash journals. Historical isolated copy/edit studies used both 68-root/11-image and a distinct 12-image corpus. One native-era optimization measured move/Undo near 7.6/7.2s → 2.4/2.2s and queued move+Undo near 15.0s → 4.4s; a separate automatic-height witness covered 22 heights without viewport overflow, not intrinsic-width/editor parity. These reported results do not validate current timing, every platform or all interleavings. Current automatic local dependency resolution and ordinary asset upload are separate retained capabilities.

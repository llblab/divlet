How it works

How a change lands

  1. 1You point

    Select a frame or an element and say what you want: “tighter hero, warmer card”.

  2. 2The agent reads, then edits

    It reads the frame and its version, then changes structure, text, styles or components by stable IDs.

  3. 3The board checks and shows it

    The change is validated, rendered and saved as one step, or refused with a reason the agent can act on.

  4. 4You keep it or undo it

    Undo reverts the whole accepted edit, whether the agent made it or you dragged something a minute ago.

Styling

Plain CSS first. Tailwind where it fits.

The inspector edits CSS properties, not class names. Layout, spacing, borders, color, type and effects are ordinary declarations that work in any project. Enable the Tailwind plugin and the same edit is stored as a utility class — and typing a class updates the controls. This page is styled with utilities only.

  • Both ways.Type pr-[37px] in the class editor and the Padding field reads 37. The utility compiles in your browser — no server, no build step.
  • No class left fighting.An edit replaces whatever utility set that property before — leading-tight, max-w-md, gap-4 — so the value you typed is the value you see.
  • What cannot be a utility stays CSS.A single border edge, a measured content size or a shared stylesheet rule remains plain CSS; nothing is dropped or flattened.

Guided tour · about two minutes

Try it without installing

On the divlet site this page opens inside the board itself, running entirely in your browser. Nothing is uploaded: your copy lives in this browser, and you can download it as a .divlet file at any time. Each step says what you should see.

  1. 1
    Open the board

    Press Edit on the board, the button at the top centre of the page (drag it aside if it is in your way). The page steps back into an artboard on a dotted canvas.

    You should see: the DIVLET button top left, three tabs bottom left, a toolbar bottom right.

  2. 2
    Select something

    Click the headline “Design in the browser.” The inspector opens on the right.

    You should see: h1 at the top, its classes in a box, then Layout, Spacing, Border, Effects and Appearance.

  3. 3
    Change a value

    In Spacing, click the number on the right side of the green padding band, type 4 and press Enter.

    You should see: the headline gain 4px on its right, and pr-1 appear in the class box. The control edited CSS; Tailwind stored it as a class.

  4. 4
    Type a class instead

    Click the class box, type pr-[37px] and press Enter.

    You should see: the padding grow to 37px and that padding field read 37. The utility was compiled in your browser; the controls read it back.

  5. 5
    Undo, redo, look back

    Press Ctrl+Z (⌘Z on a Mac) twice, then Ctrl+Shift+Z once. Open the History tab at the bottom left.

    You should see: each accepted edit undo and redo as one step, and History list them.

  6. 6
    Hand it to an agent

    This site is its own MCP provider. Connect your agent to it by URL and ask it to change the headline; the tools run in a browser page the adapter opens, and the same edit lands on the page.

    npx -y @divlet/mcp --connect https://llblab.github.io/divlet/

Install

Use it on your own projects

Requires Node.js 22.19 or later. The board binds to loopback and your project stays a file in your folder; nothing is uploaded.

Standalone

A board on your machine

Open a folder; an empty one gets a starter project, an existing one opens as it is.

npx -y @divlet/cli ./my-project

Any MCP host

Your MCP agent

Install the workflow skill once, then register the server. The agent opens the board when it needs one.

npx skills add llblab/divlet --skill divlet --global
npx -y @divlet/mcp --cwd ./my-project

Pi

The Pi extension

Brings the tools, the skill and the Agent conversation to the board. Then run /divlet in your workspace.

pi install npm:@divlet/pi

Version 0.1.1. The native project format remains a pre-freeze draft, so keep backups of projects you care about.

For agents

Seven tools, one contract

Pi, MCP and the browser board run the same tool definitions, validation and refusal codes. The skill teaches the loop: read, edit with the version you read, verify what rendered.

Open and inspect

  • divlet_openOpen a project and its local board.
  • divlet_readFrames, nodes, components, the user's selection, measured layout and history.

Change the layout

  • divlet_patchChange a frame or the project by stable IDs, at a known version. Styles are plain CSS declarations.
  • divlet_editInsert, move, wrap, duplicate, rename or remove elements.
  • divlet_frame_manageCreate, duplicate or delete frames.

Explain and recover

  • divlet_markShow the user where the agent is about to work.
  • divlet_undoUndo or redo the latest change.

Bring pages in, take plain HTML out

Static HTML pages open through the native importer, Pencil files convert through a plugin, and Markdown folders become routed sites. A source is never rewritten: divlet creates a sibling .divlet once. What comes out is ordinary HTML and CSS.

.html static pages.pen PencilMarkdown sites.divlet native

Honest boundaries

  • Layouts, not applications. HTML, SVG and CSS; no scripts or event handlers.
  • Generated pages are output. Hand edits there are reported and preserved, not imported back.
  • The browser board is a copy. It edits this site's project; images, fonts, build output and opening other projects need the local board.

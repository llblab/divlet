## P1 — persisted history and branches

Decided (operator, 2026-11-21): the browser-hosted client remembers the edit history together with its project, the History tab lists only the states a restore can reach in both directions, and the history itself is a rewritable tree — as part of the Divlet format, not as local editor state.

Extended the same day: the format should be fully deterministic and composed of patches — the top level of a `.divlet` file carries the ordered sequence of patches whose replay yields the model — and a direct edit of a managed generated page must be synchronised into that same history by the codec instead of bypassing it. That makes the log the single stored authority: a state is a position in it, a branch is a parent link, and the History tab is a view of that data rather than a second record.

Both decisions make stored history a format-owned capability: it goes through the same admission, replay proof, retention bounds and non-overwriting rules as other stored data, and it never becomes a way around writer authority. Neither is authority to advance `schemaVersion` before the first freeze, and the Node host keeps its current session-only history until the same contract is implemented there.

- [ ] **HISTORY-LOG — Make the stored project the replay of an ordered patch log.** The shape is drafted as a candidate in [docs/format.md](docs/format.md#ordered-patch-log-candidate-awaiting-approval): `base` snapshot plus ordered `entries` linked by `parent` with a `head`, one byte-stable spelling, replay-or-refuse, trimming as the only loss, explicit copy migration and output derived from replay. Before implementation the operator settles the open decisions listed there (base policy, patch identity, retained window, unreproducible-log behaviour, dropped-subtree erasure); then implement canonical writing/reading, replay proof against the shared kernel, trimming, migration and refusal paths. Verify byte-stable round trips, replay divergence refusal, trimming that keeps reachable states, and reopening a migrated project. A format freeze cannot claim a deterministic file while this is open unless the decision is explicitly deferred.

- [ ] **HISTORY-PERSIST — Keep the accepted history with the browser's project.** Store the accepted log, point identities, labels and grouping bounds so a reload, a second tab and a restart reopen the same reachable past, with the same Undo/Redo results as the session that produced it. Define retention (window, size budget, pruning order), what happens when stored history and stored content disagree, and how a refused or stale restore reports itself instead of rewriting content. Reuse the shared replay kernel rather than a second traversal implementation. Verify reopening with an untrimmed and a trimmed history, a stale/corrupt record, a second tab, cleared storage and a version-less legacy project.

- [ ] **HISTORY-TREE — Address a branch point instead of a linear stack.** Persist fork points as parent links in the log, keep both subtrees replayable, and render a branch as one special row where it was created — a tree shown linearly, not a second history view. A restore or edit must name the branch it belongs to; replay, grouping bounds and point invalidation follow the selected branch only. Verify fork, switch branch, undo/redo across a fork, refusal when a branch cannot be reproduced, and reopening a project with two branches.

- [ ] **HISTORY-RETURN — Make every step through the list returnable without asking.** Operator direction (2026-11-21): no dialog about dropping the future. A jump from the history list must itself be one Undo step, so `Ctrl+Z` comes back to the state you jumped from and `Ctrl+Shift+Z` repeats the jump, anywhere in the list; an edit made after a restore must stay returnable the same way instead of silently discarding what lay ahead, which is HISTORY-TREE's fork. Measured today: three edits, then a click on the oldest state leaves `undoStack` empty, so `Ctrl+Z` does nothing and only `Ctrl+Shift+Z` returns (`artifacts/` probes were removed; reproduce with `core/tests/history-navigation.test.ts` and `web/tests/history.mjs`). Preserve the history rules: one writer, whole-group validation before committing, stack authority moved only after the candidate persists, and no second traversal implementation. Verify jump → `Ctrl+Z` returns, repeated jumps, a jump followed by an edit, a refused navigation that changes nothing, and the same through the tools and API rather than the client alone.

- [ ] **HISTORY-CODEC — Synchronise managed-page edits into the log.** Depends on WEB-5, which still only diagnoses edited generated pages. Once an edit is admitted, it lands as one log entry through the same validated writer path — never a silent byte rewrite — keeping text/instance identity, the authored-versus-generated CSS split and resource provenance, refusing ambiguous or stale edits, and suppressing own-write import loops. A direct edit therefore becomes history like any other accepted change, visible and undoable in the same list. Verify by editing a generated page and finding exactly one new entry with correct identity, plus refused edits that leave the log and the source bytes untouched.
